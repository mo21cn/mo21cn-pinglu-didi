### 1.1 Q-02 的硬约束（请随 Q-02a 一并追认，可直接转成验收判据）

> **官方源开关必须与真实适配器同时存在，才允许置 `true`。**
> 判定式：`official_available == true ⇒ 存在真实官方源适配器`；不成立即视为违规。

理由（rev.1 未写、实测发现的对照）：`CUSTOMS_OFFICIAL_SOURCE_ENABLED` 此前是**空壳开关** ——
置 `true` 后 `/customs/sources` 会返回 `single_window.state=available`，而背后没有任何数据源。
这正是本项目要防的"看起来有"，且它恰好落在 Q-02 的兑现机制上。

### 1.2 Q-04 的三条代码事实（rev.1 的"复用 `customs_officer` 权限位"不成立）

1. 权限词表在 `backend/app/modules/entrust/access.py:61-103`，全部是 `entrust:*` 与 `org:*`，
   **没有任何 customs 相关权限位**；`member_role` 只有 `owner / admin / manager / member`。
2. 关务模块**不查权限位**：`backend/app/modules/customs/router.py:55` 只取登录态 `UserDep`，
   `:58-60` 的 `_org_ids()` 只取组织集合。
3. 可见性已被用例锁死：`test_api_visibility_is_404_not_403`、`test_api_list_only_returns_own_rows`
   ⇒ 报关记录与归类候选当前都是**个人私有 + 组织边界**，跨人不可见。

> ⚠️ 若按 rev.1 原文签字，会以为"关务专员可见他人记录"这个位已存在、只是归属未定。
> 实际情况是：那个位**不存在**，关务模块也**没有判权层**。
