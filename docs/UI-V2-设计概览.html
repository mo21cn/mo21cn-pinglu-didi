① 关键技术决定：自定义 tabBar

原型的底栏有两个位置随角色变化：第 1 位「找船 / 找货」、中间凸起位「发布货物 / 发布空船」。 原生 tabBar 是 app.json 静态配置，做不到 → 启用 tabBar.custom = true，新增 miniapp/custom-tab-bar/ 组件按当前角色动态渲染。

5 个位置的角色化映射

位置货主端船东端行为
1🚢 找船📦 找货switchTab shipper / owner
2📋 订单📋 订单switchTab orders
3（凸起）＋ 发布货物＋ 发布空船navigateTo publish/cargo · publish/ship
4⚓ 港口⚓ 港口switchTab port
5👤 我的👤 我的switchTab mine

踩坑与解法

  • app.json 的 tabBar.list 是 switchTab 白名单 —— owner 必须列在里面，否则 switchTab owner 静默失败。list 保留 5 个真实页面，组件只渲染 5 个按钮（前两位合并成一个动态位）。list 项数 ≠ 渲染按钮数。
  • 每个 tab 页 onShow 调用 syncTabBar(this)（utils/tabbar.js），刷新高亮位与角色文案。
  • 高亮位由当前路由反推（calcSelected(route)），不依赖组件自己的状态。

⑤ 已知限制与下阶段候选

  • 货源大厅为演示数据：后端没有「公开货源」接口（/cargo/shipments 只返回本人发货单）。下阶段建议新增 GET /cargo/pool（公开货源池）。
  • 订单卡的路线依赖前端富化：OrderOut 只有 cargo_id / ship_id，前端用「我的货源 + 我的船队」建 map 补全；船东视角拿不到别家货源 → 降级显示「货源 #id」。建议在 OrderOut 增加 cargo 摘要字段（name / origin / dest / weight / expect_date）。
  • 发布空船无接口 → 本机 Storage 草稿，接口上线后可一键同步。
  • 小程序无自动化测试 → 已加静态校验脚本兜底；真机联调仍需在小程序开发者工具中跑（BASE_URL=127.0.0.1:8000，后端 WECHAT_MOCK=true 时可用 dev_login_code = seed-shipper / seed-owner / seed-port 快速切身份）。
