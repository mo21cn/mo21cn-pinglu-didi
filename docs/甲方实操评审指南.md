#### ⚠️ 云端档三件必读的事

**① 档位由一行决定——别用错档**

`miniapp/config/env.js` 里的 `RUNTIME_PROFILE` 是**全小程序唯一**的环境开关：

| 取值 | 行为 | 用于 |
|---|---|---|
| `'demo'` | 走云托管 `callContainer`（微信私有协议，**免域名免备案**） | 云端档（**仓库当前值**） |
| `'dev'` | 开发者工具走 `127.0.0.1:8000`、真机走局域网 IP | **本机档（第 3–6 章）** |

> 仓库当前是 `'demo'`。**若要跑本机档（第 3–6 章），必须先把这一行改成 `'dev'`** —— 否则小程序会去连云托管，你起在本机上的后端**永远不会被访问**（现象是列表全空或提示无法连接，容易误判成后端坏了）。
> （CI 脚本另有一套自动回落 `'dev'` 的机制，只作用于 Node 校验环境，不影响此处的手动切档。）

**② 登录态 12 小时，过期需重新进一次身份**

云档用真实微信身份，令牌有效期 **12 小时**。过期后的表现通常是页面提示「登录已过期」或列表为空（**不一定报错**）。
**恢复**：回首页**点一次身份卡**换发新令牌；或「我的 → 退出登录」后重新进入。

**③ 云端演示数据目前只覆盖「委托支线」**

委托支线（组织 / 委托 / 任务 / 成果 / 异常 / 合同）**数据完整**；平台侧（货源大厅 / 船舶备案 / 订单）**尚未铺演示数据**，列表会是空的。这是**已知边界**，不是故障——见 §8 第 12 行。

#### 运维补充（甲方可跳过）

云端的演示数据初始化都是**一次性动作**，通过环境变量触发、**做完即删**：

| 环境变量 | 作用 | 回滚方式 |
|---|---|---|
| `SEED_ON_BOOT=true` | 启动期铺委托侧种子（幂等，可重复执行） | 删除该键 |
| `BIND_DEMO_IDENTITY=<openid>` | 把演示账号的 openid **过继**给真实登录账号 | 按脚本打印的 SQL 反向还原（原账号已归档，未删除） |
| `DEMO_GRANT_ORG_MEMBER=<openid>` | 给该账号补**组织成员资格**（受理台可见） | `DELETE FROM ent_org_member WHERE org_id=1 AND user_id=<id>;` |

> 两条踩过的经验，避免后人重复走弯路：
> 1. **改环境变量触发的部署会复用最近一次构建的镜像**——要让新代码生效，必须**推代码**触发一次构建；
> 2. 容器**没有 Shell**（控制台的「云端调试」只是 HTTP 接口调试器），所以**迁移与种子都已并入容器启动命令**，不需要也无法进容器手工执行。

## 3. 第一步：启动后端（≈3 分钟）

```bash
# ① 创建并激活虚拟环境（只做一次）
cd backend
python -m venv .venv
.venv\Scripts\activate           # Windows
# source .venv/bin/activate      # macOS / Linux

# ② 安装依赖（只做一次，约 1–2 分钟）
pip install -r requirements.txt

# ③ 建表 / 执行数据库迁移（只做一次）
#    ⚠️ 不要跳过：委托支线的表（ent_*）只由迁移创建，其余表才由服务启动时自动建。
python migrate.py

# ④ 开启委托支线开关（只做一次）
#    该开关默认关闭（关闭时 /api/v1/entrust 整组返回 404，用于"隐藏入口不删数据"）。
#    写进 .env.local 最省事，且该文件已被 .gitignore 忽略，不会污染仓库。
echo ENTRUST_ENABLED=true > .env.local        # Windows cmd（PowerShell: "ENTRUST_ENABLED=true" > .env.local）
# printf 'ENTRUST_ENABLED=true\n' >> .env.local   # macOS / Linux
# ⚠️ 若 .env.local 已存在（例如你自己配过其他项），请**追加**而不是覆盖上面的 > 改 >>。

# ⑤ 启动服务
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# 不想动文件的话，等价写法（临时环境变量）：
#   Windows:  set ENTRUST_ENABLED=true && python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
#   macOS/Linux:  ENTRUST_ENABLED=true python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

**启动成功的判据**（终端最后几行应包含）：

```

INFO:     Application startup complete.
```

### 5.4 验收路径 C：港域防超卖（约 5 分钟 · 通过接口文档独立复现）

**先说明一件事，避免你找不到入口**：港口运营台属于**港口方内部功能**，客户端首页只保留「货主 / 船东」两个身份入口（原「我是港口方」已下线）。因此下面给出一条**你可以独立操作、不依赖我方**的复现路径——直接用自动生成的接口文档 `/docs` 打接口。

> 其实你在 §4 已经见过这个结果了：`seed_demo.py` 的输出里有一行 `★ 防超卖拦截 409`。下面是把同一件事**亲手复现**一遍。

1. 浏览器打开 <http://127.0.0.1:8000/docs>；
2. 展开 **`POST /api/v1/auth/login`** → 点「Try it out」→ 请求体填 `{"code": "seed-port"}` → 点「Execute」→ **复制响应里的 `access_token`**；
3. 点页面右上角「**Authorize**」→ 粘贴该 token → 点「Authorize」；
4. 展开 **`POST /api/v1/auth/switch-role`** → 「Try it out」→ 请求体填 `{"role": "port"}` → Execute → **把返回的新 `access_token` 再 Authorize 一次**（这是港口身份令牌）；
5. 展开 **`GET /api/v1/port/appts-review`** → Execute → 应看到待确认预约列表，其中有一条备注为 **`演示窗口 A3`**、状态 `pending`；
6. 展开 **`POST /api/v1/port/appts/{appt_id}/confirm`** → 填入上一步那条预约的 `id` → Execute；
7. **预期结果：`409 Conflict`**，响应体为：

```json
{"detail":"档期冲突：该泊位 [09-13 14:00~09-13 22:00) 已有 2 个确认预约，并发容量 2"}
```

**这一步证明了什么**：该预约的时间窗与两条已确认预约重叠，已占满泊位的**并发容量（2）**，后端在确认时通过**行锁 + 重叠计数**判断并拒绝入库——这就是**防超卖**。

配套的对照事实（可在 `GET /api/v1/port/berths/{id}/schedule` 里看到）：

- `pending` 状态的预约**不占档期**，撤销即释放；
- 时间窗**不重叠**的预约（错峰窗口 D）可以正常确认；
- 同一套「先查后锁 + 唯一性约束」的范式，在订单域（防重复出单）与支付域（防重复支付）被复用。

> 如需在小程序界面里查看这一屏（档期甘特 / 峰值占用 / 容量预检算式），可由我方以港口方账号演示——界面能力是已开发的，只是入口不对甲方开放。

### 5.5 发货方式选择弹窗（自主发货 / 委托发货）

点底部凸起「**发布货物**」进入发布货物页（二级页）后，**先弹出**发货方式选择窗：

### 5.6 验收路径 D：委托支线（货主委托 → 组织受理，约 10 分钟）

这是本项目**除撮合交易之外的第二条主链**，也是最近一段的主要开发内容。它证明了「**平台化 + 组织化**」这层设计：货主不必自己找船，可以把事委托给服务经营主体去办，而**每一步都有留痕与权限边界**。

> **前置**：已按 §4.1 铺好委托支线数据。本机档下两个入口**分别在两个身份下可见**（这是**有意的入口隔离**，不是缺陷）：
> - **货主**身份（code `seed-shipper`）→ 看「📦 我的委托」
> - **船东**身份（code `seed-owner`）→ 看「📋 委托发货」（＝组织受理台）

#### D-1 货主侧：发起委托

| 步骤 | 操作 | 预期结果 | 这一步证明了什么 |
|---|---|---|---|
| **①** | 以**货主**身份进入 → 底部凸起「**发布货物**」→ 弹窗选「**委托发货**」 | 进入「**委托发货 · 委托给谁**」屏；刚填的货名 / 货量已带入为**草稿初值** | 起草稿**不代替用户说话**：只带客观事实（货名/量），「要办什么」的标题仍由用户自己填 |
| **②** | 选委托目标（演示数据只有一个可用目标，界面会**自动选中**并提示）→ 填「**一句话说明**」（例：`800吨钢材从南宁运到贵港，下周三装货`）→ 点提交 | 提交成功后**直接跳到委托详情页** | 服务端是**两步写**（建草稿 → 提交），但界面只给一个「提交」按钮——贴合用户"交出去"的心理模型；失败时可区分"哪一步没成" |
| **③** | 提交后**中途退出页面再进入**（或直接杀掉小程序重开） | 在途草稿被**续接**，不会重复建单 | 草稿状态落本地存储并跨页面实例恢复，避免"我以为没提交，其实提交了两遍" |
| **④** | 回首页 →「**📦 我的委托**」 | 列表出现刚提交的那条，状态为**待受理** | 与演示数据里的 3 条并存 ⇒ 写链路真的落库了，不只是界面动画 |

#### D-2 组织侧：受理与执行

| 步骤 | 操作 | 预期结果 | 这一步证明了什么 |
|---|---|---|---|
| **⑤** | 切到**船东**身份（「我的」→ 切换身份）→ 进「**📋 委托发货**」（页头「委托发货 · 经理工作台」） | 看到**委托队列**（待受理 + 已认领的任务）与**案件队列**（异常与变更） | 这是**组织受理台**，需要组织成员身份才进得来（入口按成员资格隔离） |
| **⑥** | 点开那条**待受理**任务 → 在详情页点「**受理委托**」 | 状态由 `submitted` → `claimed` | 受理是**显式动作**、可留痕，不是自动流转 |
| **⑦** | 打开 `DEMO-1 canonical · 钢材 800 吨 南宁 → 贵港`，看**运力确认** | 三条候选（公—水—公三段），逐条标注载重、船数、是否允许拼载、运价；下方有**规则校验结论** | 运力确认同样走**确定性规则 + 逐条留痕**，不是拍脑袋填数 |
| **⑧** | 看**成果**区（六类）与**版本** | 报价解析 / 采购确认 / 客户报价 / 合同评审 / 结算草稿；每次修改产生**新版本**，旧版可回溯 | 成果是**版本化**的：改了什么都留得住，且能指出"这一版是谁、依据什么产出的" |
| **⑨** | 看**异常与变更**（两宗案件） | `演示异常·原船主机故障`、`演示变更·收货港由贵港改为梧州`；每条有事件时间轴与影响范围 | 变更**不直接改数据**，而是走异常单 → 应用变更 → 触发**重校验**，保证"改了之后该复核的都复核了" |
| **⑩** | 看**财务与结算** / **专业会话** | 结算草稿与费用行；专业会话里能看到智能体的工作记录 | 财务口径独立成域；智能体全程只**产出内容**，业务数据仍由正式接口写 |

> **一句话看点**：这条链上每个"改了什么"都有记录、每个"谁能做什么"都有边界——
> 这正是把线下的"委托—受托"关系搬进系统时最难的部分。

## 9. 故障排查

| 症状 | 可能原因 | 处置 |
|---|---|---|
| 小程序红条「未连接后台 127.0.0.1:8000」/ `ERR_CONNECTION_REFUSED` | **后端没在跑**（最常见） | 回到 §3 的终端确认服务还开着；或在开发者工具点红条上的「点此重试」 |
| 本机后端明明在跑，小程序却连不上 / 列表全空 | **档位是 `'demo'`（云档）**，请求根本没打到本机 | 把 `miniapp/config/env.js` 的 `RUNTIME_PROFILE` 改成 `'dev'`（见 §2.3 ①） |
| 页面一直转圈 / 所有请求失败 | 域名校验未关闭 | 开发者工具「详情 → 本地设置」勾选「不校验合法域名、web-view、TLS 版本以及 HTTPS 证书」 |
| 各平台侧列表全是空的 | **没跑 `seed_demo.py`** | 执行 §4 |
| 委托支线页面全部报「接口不存在 / 404」 | **`ENTRUST_ENABLED` 没开**（该开关默认关闭） | 按 §3 第 ④ 步在 `backend/.env.local` 写入 `ENTRUST_ENABLED=true` 并重启后端 |
| 委托支线报「表不存在」 | **没跑迁移**（`ent_*` 表只由迁移创建） | `cd backend && python migrate.py`（幂等，可重复跑） |
| 「我的委托」有数据，但「委托发货」提示「还没有加入服务经营主体」 | 用的是**货主**身份，受理台需要组织成员身份 | 切到**船东**身份（`seed-owner` 即演示组织经理）；见 §8 第 5 行 |
| 云端档页面提示「登录已过期」或列表为空但不报错 | 令牌 **12 小时**有效期到了 | 回首页**点一次身份卡**换新令牌（见 §2.3 ②） |
| `seed_demo.py` 报连接错误 | 它是**通过 HTTP 调后端**铺数据的，后端没起就会拒连 | 先确认 `/healthz` 返回 200，再跑种子脚本 |
| `seed_entrust_canonical.py` 报「口径不符」并拒绝执行 | 之前跑过端到端校验，委托货量已被改成 1000 吨 | 这是**有意的防污染守卫**。要重来：删 `backend/*.db` → `python migrate.py` → 按 §4 / §4.1 重铺 |
| 端口 8000 被占用 | 上一次的后端没退干净 | Windows：先 `netstat -ano` 找到占用 8000 的 PID，再 `taskkill /PID <PID> /F`；macOS/Linux：`lsof -i :8000` 后 `kill <PID>` |
| 点身份卡提示「登录失败」 | 后端未就绪 / 该身份未注册 | 先确认 `/healthz` 返回 200；错误弹窗会写明**失败环节 + 真实原因 + 处置建议** |
| 导入工程后提示 AppID 无效 | 仓库内的 AppID 属于**我方主体**，你的微信号不是它的开发者 | 导入时选择「**测试号**」（本机档），或直接扫码进体验版（云端档） |
| `pip install` 很慢或失败 | 网络问题 | 换国内镜像：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 预约档期日期看起来"过期" | 演示数据是相对创建日期生成的 | 重新执行一次 `seed_demo.py`（建议评审当天执行） |

若需要带着结论看演示，可按下表定位"亮点"对应的**屏幕上能看到的证据**。

| 关注点 | 在哪里看 | 为什么重要 |
|---|---|---|
| **确定性内核不经大模型** | 撮合结果页头卡「确定性内核 · 零 LLM」；合同页头卡「核心条款零 LLM」 | 撮合、支付、防超卖、订单状态机**永不经过大模型**——这是工程底线一 |
| **智能体不直写业务数据** | 一句话发货只产出**草稿**，需人工确认后走正式接口发布 | 工程底线二：智能体写操作一律经业务领域 API，可回滚可审计 |
| **交易全链路留痕** | 订单五时间戳、支付双流水号 + 四时间戳、资金状态时间轴 | 工程底线三：实名、留痕、复核 |
| **防超卖（并发安全）** | 港域重叠预约被 409 拦下；预约确认用行锁 + 重叠计数 | 同类问题（防重复出单、防重复支付）在订单、支付域用同一范式 |
| **资金流与订单流一致性** | 撤单 → 支付单自动退款 | 退款不开放独立端点，只由撤单联动，避免两条状态机各说各话 |
| **风险识别规则引擎** | 合同页风险点列表（未支付 / 未锁价 / 装货临近 / 证书临期 / 液货危险品 / 滞期费 / 保险 / 违约金 / 在途不可抗力） | 9 条确定性规则，**不依赖大模型**；另有合规预检 9 条规则用于发布前拦截 |
| **工程化程度** | GitHub 仓库的 PR 记录、CI **6 个 job**、CHANGELOG、Git Flow 分支 | 每个批次 = 一个分支 = 一个 PR，CI 全绿后合并；可查可溯 |
| **委托支线：权限与入口隔离** | 「委托发货」（受理台）与「我的委托」（货主侧）在不同身份下可见 | 谁能做什么由**服务端权限矩阵**决定，不是前端藏按钮；接口层同样校验（前端绕过也无效） |
| **委托支线：变更不直接改数据** | 异常与变更案件 → 应用变更 → 触发**重校验** | 改完货量/港口会重新跑该复核的项，避免"改了但没复核"——线下流程里最容易出事的地方 |
| **委托支线：成果版本化 + 字段来源追溯** | 成果区每次修改生成新版本；合同派生逐字段标注**来源**（人工录入 / 成果引用 / 规则推导） | 合同上的每个数字都能回答"从哪来的"，这是可审计的前提 |
| **质量自证能力** | §6 的十个校验脚本（合计 **2300+ 条断言**，另有 29 JSON / 24 页面 / 70 路由引用 / 413 事件绑定 / 185 走查锚点的结构校验） | 不是"人工说好用"，而是**可复现的自动化断言**，且已全部纳入 CI 自动执行 |
