## 0.2 备案已获（个人主体）后的上线可行性判定（2026-09-24）

**背景**：小程序备案以**个人主体**（莫伟）申请并已通过；该账号**不具备收付款能力**（个人主体不可开通微信支付）；
用户明确定位为"**仅作为开发调试使用**"。

### 第 ① 步：先确认"这个号码真的是这个小程序的备案号"（1 分钟，必须做）

工信部备案编号有**四种**，看**后缀**即可区分：

| 类型 | 格式 | 例 |
| --- | --- | --- |
| 主体备案号 | 省简称 + `ICP备` + 主体序列号 | `桂ICP备2026021348号` ← **短信里给的是这个形态** |
| 网站备案号 | …+ `-n` | `桂ICP备2026021348号-1` |
| **小程序备案号** | …+ `-n`**`X`** | `桂ICP备2026021348号-1X` |
| App 备案号 | …+ `-n`**`A`** | `桂ICP备2026021348号-2A` |

> **小程序备案号必须以 `X` 结尾。** 短信展示主体号是正常现象（首次备案时主体号与小程序的 `-1X` 会一并生成），
> 但**请以小程序后台为准**：`mp.weixin.qq.com` → **设置 → 基本设置 → 备案信息**，
> 应能看到形如 `桂ICP备2026021348号-1X` 的**小程序备案号**且状态为「已备案」。
> ⛔ 若那里**没有**该小程序的服务项号，说明备案还没真正落到这个 AppID 上，需回后台继续走完流程。

### 第 ② 步：为什么"有备案 ≠ 能上线"——三道硬墙

备案解决的是"**能不能发布**"的前置；而提审时还要过"**功能与主体是否匹配**"。个人主体在这三处受限：

| # | 硬墙 | 依据 | 对本项目的影响 |
| --- | --- | --- | --- |
| **1** | **服务类目：个人主体可选范围里没有货运/水运/港口** | 微信《小程序开放的服务类目 · 个人主体》清单里，与物流相关的只有「快递业与邮政 → 快递、物流 → **查件（仅查询）**」「装卸搬运」等**纯查询/纯工具**类目；「货物运输」需《道路运输经营许可证》、「水运」需《水路运输/港口经营许可证》——**这些只对非个人主体开放** | 本项目核心功能是**发布货源 → 撮合 → 下单 → 结算 → 委托受理**，远超"仅查询"。**选不到匹配类目 ⇒ 提审按"类目与功能不符"驳回**（这是官方口径里的驳回主因） |
| **2** | **深度合成（AI）类目不对个人开放** | 腾讯云 CloudBase 官方文档原文：「**深度合成类目仅向非个人主体（即企业或组织）开放。个人主体小程序无法申请此类目**」；且需提供算法备案 + 合作协议，AI 生成内容须显著标注"AI 生成" | 本项目有五个智能体（货源解析、合同生成、客服问答、合规预检、意图路由），**属生成式能力** ⇒ 走正式审核必须申该类目，**个人主体申不了** |
| **3** | **个人主体仅限非经营性用途，且不可开通微信支付** | 个人主体：❌ 微信支付 ❌ 附近的小程序 ❌ 直播组件 ❌ `web-view` ❌ `getPhoneNumber` 等高级接口 | 本项目的平台撮合与交易形态属**经营性**；支付环节无法真实闭环（本项目已按"不宣称资金到账的样本"设计，故**演示无碍**，但正式版会被判"功能不完整/超范围"） |

**顺带排除的几项**（个人主体的限制，但本项目**不受影响**）：`web-view`（个人不可用 ⇒ 本项目**未用**，页面全部原生实现）、
`getPhoneNumber`（未用，登录只取 openid）、附近的小程序 / 直播组件 / 卡券（均未用）。

- **"面向公众正式上线"在当前个人主体下不可行** —— 见路径 B，且**主体类型不可"修"，只能"换"**。

| 项 | 说明 |
| --- | --- |

⚠️ **主体类型无法直接"修改"**，只有两条路，且**备案都要按新主体重办**（备案绑定"主体 + 服务内容"）：

| 路线 | 做法 | 确定性 | 备注 |

### 1.2 小程序备案（**硬门槛：先备案，才能发布**）

- 依据《互联网信息服务管理办法》等，**自 2023-09-01 起所有境内小程序必须先备案**；
  已上架未备案的会被逐步清退。
- 入口：微信公众平台 → **设置 → 小程序备案 → 去备案**（未上架的在首页有「去备案」入口）。
- 流程与周期：
  1. 填写**主体信息 / 主体负责人 / 小程序信息（Appid、名称、**服务内容标识 1–2 个**）/ 小程序负责人**；
  2. 小程序负责人**人脸核身**（白/浅色背景、免冠、不遮面）；
  3. **平台初审 1–2 个工作日**；
  4. **工信部短信核验**（号码 12381，须 **24 小时内**在 `beian.miit.gov.cn` 完成，
     超时会被自动驳回）；
  5. **通管局审核 1–20 个工作日**（常见 7–15 天）；
  6. 备案号下发 ⇒ **才能进入版本发布/提审**。
- **✅ 本项目状态（2026-09-24）**：**已办** —— `桂ICP备2026021348号`，主体「莫伟」（个人），
  审核通过日期 **2026-09-16**。⚠️ 短信给的是**主体备案号**形态，需按 §0.2 第①步在后台确认
  小程序服务项号（应以 `-nX` 结尾）。
- ℹ️ **备案号后缀速查**（判断"是不是这个小程序的备案"）：无后缀＝主体；`-n`＝网站；**`-nX`＝小程序**；`-nA`＝App。
  依据 YD/T 3565-2019 与工信部《关于调整非经营性互联网信息服务备案编号的通知》。

- ⚠️ 若要**自定义域名**（不用云调用），该域名须**单独 ICP 备案**且与小程序主体一致。

- ⚠️ **备案与主体绑定**：主体变更/换账号后，须**先注销原备案、用新主体重新提交**，
  且服务内容标识须与新主体经营范围相符，否则管局驳回（§0.2 路径 B）。

### 1.3 服务类目与行业资质（**本项目最大不确定项**）

《微信小程序资质文件列表》里与本业务直接相关的类目：

| 一级类目 | 二级/三级 | 所需资质（节选） |
| --- | --- | --- |
| **物流服务** | 货物运输 | 《道路运输经营许可证》（经营范围需含**网络货运**） |
| **交通服务** | 水运（船企） | 《水路运输许可证》 |
| **交通服务** | 水运（港口） | 《港口经营许可证》 |

若按**平台型信息撮合/承运**（多货主发布货源、多船东接单、平台撮合与结算）经营，
行业通行门槛是**"三证一认定"**：

1. **增值电信业务许可证（ICP / EDI）** —— 经营性互联网信息服务；
2. **网络安全等级保护备案（建议三级）** —— 公安网安部门；
3. **线上服务能力认定** —— 省级交通运输主管部门（含接入省级监测系统）；
4. **《道路运输经营许可证》**（经营范围：**网络货运承运平台经营**）—— 县级交通运输主管部门。

⛔ 未取得即开展网络货运承运经营，属**无证经营**（责令停止、没收违法所得并处罚款）。
**这一项决定上线形态**：若先以"船货撮合信息平台"形态上线，需与甲方确认可接受的类目与资质边界；
若宣称"承运"，则必须先办齐上述证照。

### 1.5 内容与功能合规（审核口径）

- **内容安全**：UGC（会话消息、附件）与**模型生成内容**需具备审核/过滤能力
  （微信提供 `msgSecCheck` / `mediaCheckAsync` 等内容安全接口）；
  含 AIGC 能力还涉及《生成式人工智能服务管理暂行办法》。→ 本项目**未接**。
- **账号体系**：必须有可用的**退出与注销**功能（本项目有退出、**无注销**）。
- **功能完整**：禁止空白页、测试内容、未完成功能；**存量的"演示"字样数据会被当作测试内容**。
- **名称/图标/简介**与实际功能一致；不得使用绝对化用语、不得侵犯商标/著作权；
  素材（图片/字体）需有授权。

## 4. 建议的最短路径

> 分两条轨：**"调试/验收"轨今天就能走完；"正式上线"轨的周期由外部流程决定。**

### 4.1 调试 / 验收轨（我方即可推进，不依赖甲方）

1. **上传代码 → 后台设为体验版**，把甲方与相关同事加为体验成员（个人主体上限 **15 人**）。
2. 配合《甲方实操评审指南》§2.3 的**云端演示环境**，形成"体验版 + 云托管"的一整套可转发验收环境。
3. 按 §0.2 第①步**确认备案落位**（后台看是否已有 `…-1X` 的小程序备案号）。

### 4.2 正式上线轨（外部流程长，**先启动**）

1. **本周（甲方）**：确认经营形态 → 决定用哪个**营业执照**（企业/个体户）→ 启动**主体变更或新注册小程序**。
2. **本周（我方）**：配置**隐私保护指引**（先按现有采集项申报，后续变更再更新）→ 提审前最容易被卡的一步。
3. **下一迭代（我方）**：**账号注销** + **内容安全**接入（二者都是代码项，可并行开工）。
4. **提审前（我方）**：处理**空壳页面与"演示"数据**（隐藏未开放入口 / 替换文案），跑一遍
   《甲方实操评审指南》的验收清单确认无空白页。
5. **资质与备案（甲方）**：按所选类目办证；若按"网络货运"承办，需预留**数月**（ICP/EDI、
   等保三级测评、线上服务能力认定、道路运输经营许可证）。**备案需用新主体重办**。

> ⚠️ 顺序要点：
> ① **主体类型在类目之前** —— 类目是"主体能选什么"决定的，主体不对，办再多资质也选不上；
> ② **备案与资质是外部流程**（周期不可控），必须**先启动**；
> ③ **隐私指引、注销、内容安全、AI 标识**是内部代码/配置项，可与之并行 —— 且**它们与主体类型无关**，
>   所以**现在就可以开工**，不必等甲方定主体。
