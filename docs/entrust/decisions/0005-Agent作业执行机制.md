# DR-0005：Agent 作业的执行机制（持久化作业表 + 租约，不引入队列中间件）

- 状态：**已采纳**
- 日期：2026-09-13
- 关联：ENT-011（S2 第 5 条「作业表 + worker」）、AC-15（重启不丢任务、重试不重复副作用）、
  AC-08（输出校验失败等于不做业务变更）、AC-09（提案 ≠ 动作）

## 背景

R1 需要一个能承载 AG-01 / AG-02 的异步作业机制，且必须满足：

1. **重启不丢任务**：进程崩溃后作业还在，能被重新执行；
2. **重试不重复副作用**：同一作业不会产生两份业务结果；
3. **输出校验失败等于不做业务变更**：校验不过的产出不得留下任何业务痕迹；
4. **确定性 fixture 可在 CI 全链路跑通**：CI 不能依赖真实模型、网络与付费额度；
5. 不新增向量库、不做多模型集成、不做自治群聊（计划 §3.4）。

## 备选方案

| 方案 | 重启不丢 | 重试不重复 | CI 可跑 | 新增依赖 | 结论 |
| --- | --- | --- | --- | --- | --- |
| A. 内存队列 / `BackgroundTasks` | ✗（进程即队列） | 需另建幂等 | ✓ | 无 | **否决**：不满足 (1)，是致命项 |
| B. Celery / RQ / arq 等任务队列 | ✓（需 broker 持久化） | 需另建幂等 | 需起 broker | Redis/RabbitMQ + worker 部署 | **否决**：R1 体量下新增两套基础设施（broker + 常驻进程），且 (2) 仍要单独实现 |
| C. **持久化作业表 + 租约 + 无常驻进程的 worker 单步**（采纳） | ✓（作业行在库里） | ✓（状态机 + 幂等键 + 仅 succeeded 落信封） | ✓（fixture 直跑） | 无 | **采纳** |

## 决定

1. **作业落库**（`ent_agent_job`），状态机
   `queued → running → succeeded / failed / cancelled`；
2. **租约**（`lease_owner` + `lease_expires_at`）实现崩溃恢复：租约过期的 `running`
   作业可被重新领取，这就是"重启不丢任务"的落点；**尝试次数在领取时消耗**，
   因此"每次领取都崩溃"的作业也会被 `max_attempts` 兜住；
3. **无常驻进程**：只提供 `agentjobs.tick()` 这一步操作与显式的
   `POST /agent/jobs/{jid}/run`。生产由 cron / 平台定时任务周期调用。
   **本增量不假装已经有常驻 worker**；
4. **校验失败不落信封**：只有 `succeeded` 才写 `envelope_json`；校验失败的作业
   在数据层面就不存在"半个事实"；
5. **作业层没有任何写成果的代码路径**：信封是提案载体，把它变成成果必须再走
   一次显式写接口（AC-09 靠结构保证，不靠约定）；
6. **`POST /agent/jobs/{jid}/run` 不要求 `Idempotency-Key`**：它的幂等来自状态机
   与租约 —— 重复调用会被 `claim_job` 判为"已结束"或"租约仍被持有"而拒绝（409），
   连一次尝试都不会多消耗。这比键重放更强：键重放只防重复**提交**，
   这里防的是重复**执行**。

## 后果

**正面**
- 零新增依赖与零新增部署单元；CI 不起 broker 也能验证整条作业链路；
- 崩溃恢复、有界重试、取消、尝试日志都是同一张表上的状态转移，行为可被单测穷举；
- "提案不产生副作用"是结构性事实，不是纪律约束。

**负面 / 代价**
- 作业吞吐受数据库与调度频率限制；高并发场景需要改造成真正的队列
  （届时 `claim_job` 的语义可原样保留，只换调度层）；
- 无常驻进程意味着**延迟依赖调度周期**，"提交后立刻出结果"必须由显式
  `/run` 触发 —— 这在 R1 是刻意的（经理点一下才跑），不是妥协；
- 租约粒度是整条作业，长作业需要把 `lease_seconds` 调大或引入续租
  （R1 的作业都是单次模型调用，暂不需要）。

## 未覆盖（如实登记）

- **真实模型质量未验证**：fixture 只保证结构同构，不证明模型输出好用；
- **MySQL 上的作业并发（同一作业被两个 worker 同时领取）未在 CI 真实执行**——
  目前只靠单条条件 UPDATE 的受影响行数裁决，与认领委托（AC-03）同构，
  但缺少 MySQL 侧用例；登记为后续增量（与 DR-0002 一并处理）；
- 附件文本提取（S1 第 6 条）未实现，AG-02 当前以操作者粘贴的报价文本为输入。
