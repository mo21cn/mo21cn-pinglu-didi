## 1. 背景（三条事实）

**事实 ①：E-5 已被押后，但合同 D1-15 仍然有效。**
`DEMO-1-readiness.md` E-5 记「HO 已裁：押后」到「备案号下来、做全量上线准备工作清项」；
而合同 D1-15 原文要求 `One supported value is changed by the witness`（见证人改一个值），
且 S5 出口判据是「全部 D1 行**有结果报告**」。
⇒ 两者如果不显式对齐，就会出现**两种误读**：要么把「押后」当成 E-5 已消失，
要么把「押后」当成产品功能可以不做。

**事实 ②：开发方提出的「全量真手势确认」不在合同口径内，且已登记过同模式。**
合同 §10.1 是**一个 13 步、15–20 分钟的主演示脚本**（不是 23 个页面逐页真手势）；
§10.2 明文 `Not every negative must consume presentation time. Automated/API evidence may
accompany the main UI run, provided its scope and candidate version are explicit.`；
§10.1 末句把见证人定位为**检查者**（`may pause and inspect IDs, revisions, evidence, and
changed values`），并明说录屏/检查点**不能替代**缺失的强制执行证据。
`DEMO-1-plan.md` §9 建议 4 已登记同一模式：`把「弹层弹出」之前的所有步骤自动化，
只把最后一下点击留给人，人点完由脚本自动取证并回填记录表`。

**事实 ③：主脚本 13 步目前只有 2 步可跑。**
第 1 步（客户提交 + A1 受理）与第 13 步（重进检查同一条持久记录）归 S1，**已实现**；
第 2–3 步归 S2、第 4–7 步归 S3（**客户侧 0 实现**）、第 8–12 步归 S4，**均未开发**。
⇒ 现在做「全量见证」时**见证对象尚不存在**。

## 2. 裁定

### 2.1 裁定一：E-5 维持押后，但**限定为「HO / 甲方亲自见证」的安排**

- 「押后」的**边界**是：**押后的是人类的现场见证**，**不是**被测功能的开发与验证。
- **照常开发、由开发侧验证**的四件事：**改值**／**重算**／**校验**／**刷新后持久化**。
- ⚠️ **自动化证据不得被记录或标注为人类见证证据**（与合同 §10.3 一致：
  方法未覆盖被声称的行为 ⇒ `LIMITATION` ⇒ 不计入通过）。
- 见证完成前的可交付状态：**「DEMO-1 可演示候选」**。
- ⚠️ **见证完成前不得宣称完整 DEMO-1 已验收**。
- 登记去向：本决议 ＋ `DEMO-1-plan.md` ＋ `DEMO-1-r1-remainder.md`（余量台账）。
  **保留原合同、不修改历史**。

### 2.2 裁定二：批准 **B → A** 提前执行（先 B 后 A）

- 顺序**不可颠倒**：B 是 A 的前置（探针要能**反复**跑，就要能回到一致可复制的起点）。
- 完成后**立即进入 S2**；⚠️ **不得把 A / B 扩充成新的长期前置阶段**。

**B 的边界（最小隔离复位）**

1. 允许**重建专属库**或**恢复快照**，**不强制逐表清空**；
2. **仅作用于明确指定的隔离环境**，**不得触碰开发主库或生产数据**；
3. 负责校验四条一致性：**身份 / 授权 / 业务状态 / 附件 / 作业状态**；
4. 至少验证「**运行并改变状态 → 复位 → 再次运行**」**可以重复**；
5. ⚠️ **不得**要求「现在就先依赖 S4 结案能力」的「已完成历史委托」；
6. ⚠️ 本轮完成**不得标记 BP-05 或 D1-17 全部完成**。

**A 的边界（一次有明确出口的交互探针）**

1. 面向 **S2** 及 **DEMO-1 主脚本真正需要的操作**；
2. **复用已有有效证据**，不重复做「已有可走路径」的探路；
3. 每项必须记录 7 个字段：**业务动作 / 运行环境 / 输入方式 / 可观测结果 / 工具限制 /
   替代路径 / 对产品设计的约束**（schema 落 `DEMO-1-gesture-matrix.yaml`）；
4. **直接调用页面方法或接口可以证明业务结果，但不能替代真实点击或触摸的交互证据**；
5. 关键动作应有**可见、可操作的真实入口**；
6. 不应只依赖**长按 / 滑动**或**工具无法操作的原生层**；
7. 每项出口：**找到可用路径** 或 **确认限制并给出替代方案**，二者之一即**结束该项**；
8. ⚠️ **不开展无限期的手势自动化专业研究**。

### 2.3 裁定三：探针**不扩充数量**（固定 5 项），五项**原文随本决议提交入仓**

- 原委：第一轮提议的备忘落在 `.workbuddy/`（被 `.gitignore` 覆盖）⇒ **复核方看不到**，
  第三题**无法为未看到的清单背书**。**这是开发方的交付错位**（见 §3·纠正三）。
- 处置：五项**原文**（含面向的 S2 工作项或主脚本步骤、以及"为什么必须现在问"）
  已落入 `DEMO-1-gesture-matrix.yaml`，**随本决议一同进仓**供逐项审定。
- **不相关项删除或替换，重复项合并**；**不须为凑项而保留无用探针**
  （已删 / 已替换 / 已合并的项在 YAML 的 `removed_or_merged` 段逐条说明）。
- ⚠️ **该项登记不阻塞 B 开工**。

### 2.4 裁定四：收口

产出 `DEMO-1-gesture-matrix.yaml`；更新 `DEMO-1-runbook.md` 的**实际完成范围**；
随后**进入 S2**。

## 3. 两处同步纠正（裁定方指出，逐条落实）

### 纠正一：**E-5 是验收安排调整，不能变成产品功能延期**

原表述的风险：就绪台账记了「押后」，容易被读成「D1-15 可以不做」。
**正确口径**：合同 D1-15 与「S5 出口判据＝全部 D1 有结果」**都仍然有效**；
被押后的只是**人类现场见证这个动作的时点**。
⇒ 对齐方式：**开发方先交付「可演示候选」；人类见证完成前，不宣布完整 DEMO-1 验收通过。**
本决议 §2.1 即该对齐条文。

### 纠正二：**B 不必等于「对原库逐表清空」**

原文（`DEMO-1-runbook.md` §6 旧版）把「新建临时库」与「复位」写成**绝对对立**，
并据此断言"换库 ≠ 复位，复位必须回到同一套环境" —— **约束过强**。
**正确口径**：

- 复位的**验收对象**是「**应用回到一致、可复制的起点**」；
- **重建专属库**或**恢复快照**都可以，**不必保留同一个数据库文件**；
- 必须处理的是**四条一致性**（数据库 / 附件 / 后台作业 / 客户端身份缓存），
  **不是文件的同一性**。

### 纠正三（开发方自查）：**交付物落在本地被忽略目录 = 未交付**

第一轮的裁定备忘写在 `E:\PL-Ship-Broker\.workbuddy\_gesture_decision_memo.md` ——
该目录被 `.gitignore` 覆盖，**复核方在 develop 与 #122/#123 里必然找不到**。
⇒ **凡是要被复核 / 引用的材料，必须落到仓库内的受版本控制路径**
（本轮落 `docs/entrust/milestones/` 与 `docs/entrust/decisions/`）。
这条已同步到协作纪律。

- **代码**：本轮新增 `backend/scripts/reset_demo_env.py`（最小隔离复位，环境专属管理脚本，
  **不对普通用户开放**）；探针本身不新增产品代码。
- **前端**：无。探针只观测，不改界面；若探针得出设计约束，**约束的落地归 S2 工作项**。
- **数据库迁移**：无。本决议不涉及表结构变更。
- **功能开关**：无。`ENTRUST_ENABLED` 语义不变。
- **对旧流程的影响**：无。复位脚本只在显式指定的隔离环境生效（安全闸见 §6 验证方式）。
- **需要同步修改的文档**：
  - 新增 `docs/entrust/milestones/DEMO-1-gesture-matrix.yaml`；
  - `docs/entrust/milestones/DEMO-1-runbook.md`：§6 **撤销"绝对对立"的论断**并写明实际完成范围；
    §7 / §9 随之一致；
  - `docs/entrust/milestones/DEMO-1-readiness.md`：E-5 行补「性质＝验收安排调整」与指向本决议；
  - `docs/entrust/milestones/DEMO-1-plan.md`：§9 落本决议指针；
  - `docs/entrust/milestones/DEMO-1-r1-remainder.md`：余量台账登记该口径。
  - ⚠️ `DEMO-1-contract-v1.0.md` **不动**。

## 5. 回退方式

- **代码回退**：删除 `backend/scripts/reset_demo_env.py` 即可；它不被产品代码 import，
  也不在 CI 门禁的必跑集合内（由 B 的自检与门禁 lint 覆盖）。
- **数据兼容性**：脚本**只作用于显式指定的隔离库**；对开发主库 / 生产库**拒绝执行**
  （见 §6）。回退不涉及数据迁移。
- **文档回退**：本决议保留原文与纠正记录，**不删除历史表述**；如需回退，
  追加新决议说明，不改本文件。

## 6. 验证方式

| 项 | 判据 |
| --- | --- |
| B 的隔离闸 | 对开发主库路径 / 非 SQLite 目标 / 未显式指定目标 ⇒ **拒绝执行且退出码非 0** |
| B 的可重复性 | 「基线 → 改变状态 → 复位 → 再取基线」两轮比对一致 |
| B 的四条一致性 | 数据库 / 附件 / 后台作业 / 客户端身份缓存逐面出结论；**做不到的面记 `NOT_APPLICABLE` 或明确的工具边界，不得声称已复位** |
| B 不越界 | 本轮**不得**标记 BP-05 或 D1-17 全部完成（D1-17 的另一半「fresh-run 与 seeded-checkpoint 可区分」归 S5-1） |
| A 的出口 | 每项 = 可用路径 **或** 限制＋替代方案；5 项全部有结论 |
| A 的诚实性 | 自动化 / 页面方法 / 接口的证据**不得**登记为人类见证证据 |

**未执行项及原因**：人类现场见证（E-5）**押后**，见 §2.1 —— 本轮**不产生**人类见证证据，
也不得把任何自动化证据标注为它。主脚本 13 步的**完整**见证不成立（第 2–12 步依赖 S2/S3/S4）。
