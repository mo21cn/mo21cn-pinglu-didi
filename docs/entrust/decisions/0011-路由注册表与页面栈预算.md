# DR-0011：路由注册表 + 页面栈预算 + 深链参数契约（处置风险 R1）

- 日期：2026-09-13
- 提出人：`feature/ENT-015-route-registry`（S2 前端切片开工前处置 R1）
- 决策人：HO
- 状态：**提议**（待 HO 确认）
- 关联：交付计划 §8 风险表 R1；UI-01～UI-05（S2 前端切片）；`scripts/verify_miniapp.js`（既有路由可达校验）

## 背景

风险 R1 的原始表述是「`app.json` 已 17 页 / tabBar 5 项，`navigateTo` 页面栈上限 10 层，
深链与返回策略须显式设计」。2026-09-13 实测现状：

| 事实 | 值 |
| --- | --- |
| `app.json` 页面 | 17（四件套 0 缺失） |
| tabBar | 5 项（`custom: true`，用 `custom-tab-bar` 组件） |
| 导航调用分布 | `navigateTo` 20 / `switchTab` 11 / `navigateBack` 7 / `reLaunch` 3 / `redirectTo` 1 |
| 当前最长声明链 | `pages/trade/match/match` = 4 层（`mine` → `assistant` → `cargo` → `match`） |
| `navigateTo` 指向 tabBar 页的 bug | **0 处**（已由 `verify_miniapp.js` 第 6 项守住） |

所以 R1 **不是一个已存在的 bug**，而是「**新增页面不需要声明任何东西就能进 `app.json`**」这一结构性缺口：

1. **栈深不可见**：`navigateTo` 撞 10 层上限时**不报错**，只表现为「点了没反应」
   （`utils/agent-entry.js` 里那句 `fail` 兜底就是为它写的）。委托支线还要再加
   UI-01～UI-05，若某条链叠到第 10 层，很难反推是哪条链、哪次改动造成的。
2. **深链无契约**：`pages/entrust/detail/detail` 深链进来若缺 `assignment_id`，
   页面会进错误态而不是被拦下；哪些页可以深链、必须带什么参数，代码里没有单点可查。
3. **既有门禁不覆盖这两点**：`verify_miniapp.js` 只查「路由可达」与「tabBar 该用哪个 API」，
   既不计算链深，也不校验深链参数。

## 候选方案

| 方案 | 描述 | 优点 | 缺点 | 风险 |
| --- | --- | --- | --- | --- |
| A | 只写一份《路由与深链约定》文档 | 零改动 | 文档不拦人；新增页面照旧无需声明 | 高：等于把 R1 留给下一个人 |
| **B** | 路由注册表 + 链深预算 + 深链参数契约，并用 CI 双向核对 | 约束做成结构；新增页面不登记就红；链深在 PR 阶段可见 | 需维护注册表；`parents` 需人工声明 | 低：注册表现有 17 页已一次对齐；门禁有 15 项自测证明非空转 |
| C | 全面改造页面，统一改走 `R.go()` 并禁止直接用 `wx.navigateTo` | 最彻底 | 要动 20 处导航 + 逐页真机验证；与 S2 当前目标（把页面做出来）抢工期 | 中：收益与 B 重叠，但改动面与验证成本高一个量级 |

## 决策

选择：**方案 B**，并把方案 C 降级为后续增量。

1. 新增 `miniapp/utils/routes.js` —— **唯一真相**的路由注册表，每条声明
   `kind`（`tab` / `root` / `detail`）、`parents`、`deepLink`（`allow` / `require-params` / `deny`）、
   `params`、`domain`、`note`；
   同时提供纯函数 `chainDepth()` / `canDeepLink()` / `resolveNavigation()` 与
   运行期入口 `go()`（栈满时退化为 `redirectTo` 而不是静默失败）。
2. 新增 `scripts/verify_routes.js`，并接入 CI `frontend-static` job。四类检查：
   - **双向一致**：`app.json.pages` ⇄ `ROUTES` 键集合（禁止偷偷加页 / 留多余项）
   - **链深预算**：`chainDepth ≤ STACK_BUDGET = 8`（`MAX_STACK = 10`，留 2 层给临时页）
   - **导航边已声明**：`navigateTo` / `redirectTo` 的**源页面**必须在目标页 `parents` 里
   - **深链契约**：`require-params` 必须列出 `params`，且不得与 `deepLink` 语义矛盾
3. 预算口径：`STACK_BUDGET = 8`。**不写 10** —— 留出的 2 层是给「预览页 / 智能入口再叠一层」
   这类运行期临时页，否则预算是纸面的。
4. **本轮不改任何页面代码**：注册表先作为**声明 + 门禁**落地。把页面导航改为 `R.go()`
   单列为后续增量 —— 那需要逐页真机验证，与「先把 UI 做出来」抢工期，且改与不改不影响
   本决策要防的缺口（缺口是「未声明即可新增」，门禁已堵住）。

理由：本项目既有立场是「把约束做成结构，而不是做成纪律」（同 DR-0004 的工具链锁定、
DR-0008 的权限按组织细分）。「记得别把链叠太深」是一条必然失守的纪律。

## 影响

- 前端（`miniapp/utils/routes.js`，纯新增，**不改任何现有页面**）：
  - 加载期不触碰 `wx`，可在 Node 里 `require`（CI 静态校验要用）；
  - `currentDepth()` / `go()` 带运行时 API 存在性判断，非小程序环境返回安全值。
- 脚本：新增 `scripts/verify_routes.js`；`scripts/verify_frontend_e2e.js` 的 `requireStub`
  登记 `utils/routes`（**未登记会落到末尾 `return {}`，页面调用时报 "xxx is not a function"**）。
- CI：`frontend-static` job 增加一步 `node scripts/verify_routes.js`（阻塞，无 continue-on-error）。
- 数据库迁移：**无**。
- 功能开关：无。
- 对旧流程的影响（AC-01）：**无**。未改任何页面、未改任何既有脚本的行为。
- 需要同步修改的文档：本决策记录；交付计划 §8 风险表 R1 的处理说明。

## 回退方式

- **代码回退**：删除 `scripts/verify_routes.js` 与 CI 中对应那一步即可恢复原状；
  `miniapp/utils/routes.js` 可保留（未被任何页面引用，删除或保留都不影响运行）。
- **数据库回退**：不适用（无表结构变更）。
- **外部能力**：无。

**注意**：回退本决策 = 重新接受「新增页面无需声明即可进 `app.json`」，即栈深与深链契约
重新变成隐形约定。回退说明必须写明这一点。

## 已知盲区（必须写明，不要当成已覆盖）

1. **工具函数来源的导航边无法静态解析**：`utils/agent-entry.js` 的 `openSmartEntry()`
   跳 `pages/assistant/assistant`，但它的**调用方页面**需要跨文件解析才知道。
   当前脚本把这类边记为 `[工具来源]` 跳过并打印，**不计入链深证据**。
   → 约定：新增页面若调用 `openSmartEntry()`，请把该页面补进 `assistant` 的 `parents`。
2. **`redirectTo` 按 push 处理**（保守）：`redirectTo` 实际会替换当前页、栈深不变，
   我们仍按 +1 计。方向是**高估**栈深，不会漏报，代价是可能早报。
3. **未校验"注册表声明的 `parents` 是否有真实调用边"**：多声明一个 `parents`
   只会高估链深，故不设为错误（避免为通过门禁而漏声明）。
4. **真机栈深未验证**：本决策不承诺"10 层上限在真机上就是这样"，只承诺
   "声明链深不超过 8"。真机验证在下一次真机走查时一并做。
