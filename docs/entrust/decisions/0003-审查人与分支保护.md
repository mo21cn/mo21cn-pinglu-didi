# DR-0003：实际审查人与分支保护

| 字段 | 内容 |
| --- | --- |
| 编号 | DR-0003 |
| 日期 | 2026-09-13 |
| 状态 | **已采纳（附现实约束声明）** |
| 决策人 | HO（对话授权） |
| 关联 | 基线报告 D3；开发规范四（PR 审查）；CODEOWNERS |

## 背景

CODEOWNERS 此前全部为占位 `@mo21cn`，main/develop 未启用分支保护。单人 + AI 协作
的现实与规范四的"独立审查"要求存在结构性缺口。

## 决策

### 1. 审查人：`@mo21cn`（HO 本人）为正式审查人

- CODEOWNERS 去掉"占位/待决"声明，`@mo21cn` 即正式归属，不再视为待办；
- 审查重点按既有路径注释执行（迁移与权限最严）。

### 2. 现实约束声明（必须诚实记录）

当前开发由 AI 代理执行、HO 验收。**AI 不能伪装成第二名独立审查人；AI 执行的合并
动作不构成审查。** 因此在团队扩充前：

- 所有 PR 由 **HO 本人在对话中明确授权后**方可合并（"HO 回复即视为授权"即为授权记录）；
- AI 不得自行把待审查 PR 标记为"已审查"或绕过等待授权直接合并；
- 本声明写入决策记录，作为过渡期治理口径；团队扩充后替换为双人审查。

### 3. 分支保护：启用，但不设"必须 PR"

对 `develop` 与 `main` 启用：

| 规则 | 取值 | 理由 |
| --- | --- | --- |
| Require status checks | ✅，必需上下文 = CI 四个 job 的名称 + db-migration 系列 | 防止红着合并 |
| Require branches up to date | ✅ | 合并前基于最新 develop |
| Do not allow force pushes | ✅ | 规范：禁止改写共享分支历史 |
| Do not allow deletions | ✅ | — |
| Require pull request | ❌（单人阶段不开） | 直推会被完全卡死；status checks + 授权流程已覆盖风险 |
| Enforce for admins | ❌ | 单人阶段保留紧急通道；团队扩充后复核 |

> 注：required status checks 只在 **PR 合并**时强制，直接 push 不受其约束——
> 这正是"不开 require PR"下仍保留检查价值的方式：走 PR 的变更必过门禁。

## 验证

- `GET /branches/develop` 返回 `protected: true`；
- CI 必需上下文与 workflow job name 一致（中文名按 check-run name 原样登记）。

## 回退

`DELETE /branches/{branch}/protection` 或在仓库设置中关闭即可。
