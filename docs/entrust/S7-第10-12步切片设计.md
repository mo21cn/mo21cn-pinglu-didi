## 1. 结论先行

1. **第 10–12 步的三条依赖链是串联的，不能跳**：
   **第 10 步**（记录交接 / 缺失证据 / 争议额外项）→ **第 11 步**（用证据解决 + 确认结算）
   → **第 12 步**（按 §6.4 前置结案）。第 12 步的 `<S4-b>` `complete` 命令，
   它的前置 4/5（结算已批准、余额已结清）**只有第 11 步的实体存在才有判据**。
2. ⭐ **"交接"不需要新建实体**：合同 S4 段第 4 条明写
   `Do not invent a "handover artifact" when handover is represented by a task.`
   ⇒ 交接＝**任务**（`ent_workflow_task`，`task_type` 里的装卸/交接类 ＋ 它要求的证据）。
   这与本仓"DR-0016 任务/成果影响映射"是同一套东西，**不要**另起一张 `ent_handover` 表。
3. ⭐ **真正缺的是「费用行」这一个实体**：合同 S4 段第 9/10 条要求的
   `receivable/payable lines` ＋ `one extra waiting-time charge`，字段面已由合同点名
   （`quantity` / `unit` / **Decimal** `amount` / `currency` / `counterparty` / `basis` / `status`），
   且第 10 条要求 **disputed 不得进 confirmed totals**。
   实测：全仓 **34 张 `ent_` 表里没有它**（§2）⇒ 这是第 10 步的**唯一新建实体**。
4. **顺序建议**：先做 **S7-1（费用行 ＋ 争议标记）**，再做 **S7-2（缺失证据的等待条件）**，
   最后才是 **S4-b（`complete` ＋ 五类前置）** —— 反过来做，前置 4/5 没有判据，
   只能写出一堆恒不满足的检查（那是"假装做了"）。

## 3. 建议的切片拆法（**供排期，不构成承诺**）

| 切片 | 内容 | 依赖 | 规模判断 |
| --- | --- | --- | --- |
| **S7-1** | **费用行**：新表 `ent_charge`（`assignment_id` / `direction`(receivable/payable) / `charge_kind` / `quantity` / `unit` / `amount` **Decimal** / `currency` / `counterparty` / `basis` / `status`(draft/confirmed/disputed/resolved/rejected) / `disputed_reason` / `resolution_method` / `revision`）；命令 `record_charge` / `confirm_charge` / `dispute_charge` / `resolve_charge`；读端点 `GET /assignments/{id}/charges`（含**已确认合计**，Decimal 字符串，**争议行不计入**） | 无（可独立先做） | 中（迁移 ＋ 4 命令 ＋ 读模型 ＋ 权限 ＋ 并发） |
| **S7-2** | **缺失证据的等待/阻塞条件**：把"某任务缺必需证据"变成一条**可查询、可解除**的条件（挂任务上，不新建"证据"实体）＋ 可执行补救（派一条补救任务） | S7-1 不依赖；但建议先做 S7-1（两者都动"读模型"） | 中 |
| **S4-b** | **`complete` 命令** ＋ §5.4 **五类前置**（任务全完成 / 交付证据齐备 / 无未解决 critical 案件 / 结算已批准 / 余额已结清）＋ **逐条报缺**（409 带 `missing[]`）＋ 幂等 ＋ `revision` 并发（409）＋ 客户确认 | **S7-1 ＋ S7-2**（前置 2/4/5 的判据来自它们） | 中大 |
| **S7-3** | **结算草稿 ＋ 确认 ＋ 外部付款证据**（§11，demo 明标 sample/manual，照 `ent_contract_signature_evidence` 的先例） | S4-b（或与之并行） | 中 |
| **S4-c** | 受控重开 `completed → claimed`（理由 ＋ 事件留痕） | S4-b | 中 |

⚠️ **一处口径提醒（来自 S4 设计 §7.1）**：加 `STATUS_COMPLETED` 常量会连锁到前端的
`STATUS_META` / `STATUS_ORDER` / `STATUS_HINT` 三张表（静态门禁要求逐格一致），
而 `STATUS_ORDER` 派生工作台筛选条 ⇒ **代码取值域与前端三张表必须与 `complete` 命令同一个提交**，
否则会出现一个"没有数据能处于该状态"的筛选片。
