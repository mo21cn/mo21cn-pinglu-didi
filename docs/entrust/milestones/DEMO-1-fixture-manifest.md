**不是什么证据**、由哪一步演示使用"。夹具**不是**软件行为的替代品，它只提供演示的输入。

### F-1 说明

- **是什么**：一份内河货运报价单**样件**（钢铁货 1200 吨、南宁 → 贵港、公—水—公、CNY 明价
  45.00 元/吨、有效期至 2026-12-31、含项与不含项、口径声明）。`text/plain`，可直接被
  既有提取器读出文本（不需要 OCR）。
- **怎么用**：演示时由 A1 在会话屏「上传报价单」真上传，再看提取结果，然后引用它调用 AG-02。
  同一份文件也被 CI 的端到端 job 用**真 multipart** 上传（见 §3），保证演示与自动化用的是同一份输入。
- **它不是什么证据**（合同 §3.2）：
  - 不是真实航运报价，**不宣称**该航线可运营、有航行许可或承运人有可用运力；
  - 不是对客报价（它是**供应商侧**报价，两者口径不同，不得互相替代）；
  - 不是供应商/运力确认 —— 成交类结论必须另走"证据支撑的采购确认"；
  - 不是"已上传 = Agent 已读到"：只有提取完成后附件才有文本（见 §2）。
- **可信度口径**：`operator_input`（人当场粘贴）比 `attachment_text`（附件提取）更强，
  两者在 `source_refs` 里是**不同的 kind**，不得混引。

## 3. 自动化侧怎么用同一份夹具

CI 的「前端端到端」job 在 bootstrap 阶段用**真 multipart** 把 F-1 上传到演示委托授权下，
再触发提取，并断言「上传 → 提取 → 引用 → AG-02 读到文本」这条链在真实后端上成立。
⇒ **演示输入与自动化输入是同一个文件**，不存在"演示用 A、CI 用 B"的分叉。
