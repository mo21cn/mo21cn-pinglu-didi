### 1.1 附带发现（把第 2 条从"漏记"推进到"可定档"）

同一次运行（X3）里，**同一个选择器**出现两种结果：

### 6.1 先登记一处**我被纠正的判断**（⛔ 不再沿用）

我上一轮写：「模型不可用时第 2 步 AG-02 必失败 ⇒ **不可能连跑 13 步**」。

HO 裁定：**这混淆了"业务目标"与"实现手段"。** D1-05 要证明的是
「**模型不可用，经理人仍能完成同一业务生命周期**」，它**不要求**模型不可用时 AG-02 成功。
正确的替代关系：

| 正常路径 | 无模型路径 |
| --- | --- |
| Agent 解析报价、产生提案 | **经理人工填写／组装**必要业务成果 |
| 经理核对、采纳或更正 | 经理核对并确认**人工录入结果** |
| 发布 → 客户接受 → 合同 → 履约 → 结算 → 结案 | **沿用相同业务流程继续完成** |

⇒ **无模型路径可以更换第 2–3 步的操作方式，但不能省略其需要产生的业务数据。**
我那句推论等于把"AG-02 不可用"当成了 D1-05 的判据 —— 它是实现手段，不是业务目标。

### 6.2 本阶段只做三件事（优先级由 HO 定，**D1-05 第一**）

* **剧本**：**从新委托开始** → 第 2–3 步**经现有人工入口**建立所需成果 → 同一委托继续
  客户接受 → 合同 → 变更 → 履约 → 结算 → **结案** → **重载**。
* **人工入口的两条候选**（落地时先定一条，⛔ 不新建 OCR/扫描框架）：

  接受→合同→变更→履约→结算→结案→重载」。
  ⛔ 不以"AG-02 失败"充当证据；⛔ 不以"扫描件转录成功"单独关闭。
* **章节形态**：把现有 `chain-manual` 升级为**两段式**（附件分支 ＋ **业务分支**），
