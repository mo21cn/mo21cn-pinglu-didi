### 1.1 附带发现（把第 2 条从"漏记"推进到"可定档"）

同一次运行（X3）里，**同一个选择器**出现两种结果：

* `④a`：`count('[data-df="qty-unit"]') = 0` ⇒ 判 FAIL；
* `④b`：`quantityForm = {'quantity': '950', 'unit': '吨', 'basis': …}` ⇒ 判 PASS。

`case.js:117` 里 `quantityForm.unit` 的**初值是空串**，`case.wxml:279-287` 的单位输入框是**无条件**挂在同一 `wx:if` 块里的（`data-df="qty-unit"`），写入走的是**按选择器的真实元素动作**（`wechatide_client.py:545`）。⇒ `unit` 能变成 `'吨'`，说明**该元素存在且 `bindinput` 真的执行了**；`④a` 的 0 更像是 `count()` 通道的**假 0**（该函数 docstring 已记过一次同类故障：`wechatide_client.py:425-449`）。

⇒ 定档方向：**先按"探针通道"复现，再谈产品**。⛔ 不直接判产品缺陷，也 ⛔ 不直接标 `LIMITATION`（见任务 A4）。

## 3. 执行顺序与闸门

```
A3 ─┐
A1 ─┼→ A2 ─→ A5 ─→ A4(需实例) ─→ A6/A7 ─→ 门禁16/16 ＋ CI ─→ 更新 HEAD → 合并 #184（HO 有条件同意）
    └────────────────────────────────────────────────────────────┘
→ B1（一个保活窗口）→ B3 → B2（后端单开）→ C1 → HO 终验（C2）
```

* **先合并后取证据**：A 组只改脚本与文档 ⇒ 值得先形成"固定候选"；B 组全部在固定候选上取证。
* **保活窗口约束**（已实测）：`--prepare-ide --keepalive 10800` 的持有者**跑满即正常退出**、认领文件自动撤销、IDE 随之 0 ⇒ **一个 keeper 只覆盖一个窗口**；跑链用 `--min-keepalive-left`（≥ 整轮 × 1.5），**把整个复验计划塞进一个窗口**。
* ⛔ 不给闸门加"忽略"开关；⛔ 并发启动的绝对唯一性本轮**不扩建**（维持单控制者，HO 已裁定）。

## 4. 不做什么（HO 明示 ＋ 本项目铁律）

1. ⛔ 不为原生文件选择器**扩建 OS 自动化**；上传失败保留待查。
2. ⛔ 不要求所有正负例**塞进同一章同一轮**；结案拒绝与成功**同一张单**即可，独立拒绝证据也可引用。
3. ⛔ 不建设**通用环境管理平台**（复位演练一次即可）。
4. ⛔ 不把 `FAIL` **自动**改判为 `LIMITATION`（实例轮次只是诊断信息）。
5. ⛔ 不用"新增规则 / 技能条款 / 大量全量复跑"代替交付。
6. ⛔ 不为刷绿放宽断言（尤其 A1：`settlement_stale` 是**正确行为**，不能靠改判据绕过）。
7. ⛔ 合并 PR 一律等 HO 显式授权（DR-0003）。
