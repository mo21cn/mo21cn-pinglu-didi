# 决策记录模板

> 用途：所有未决工程选择按此模板记录，随 PR 一并提交，便于追溯与回退判断。
> 位置：`docs/entrust/decisions/NNNN-简短标题.md`
> 编号：从 `0001` 起顺序递增。

---

## 模板

```markdown
# DR-<编号>：<一句话决策标题>

- 日期：
- 提出人：
- 决策人：
- 状态：提议 / 已采纳 / 已否决 / 已取代（被 DR-xxxx 取代）
- 关联：需求 WF-xx / UI-xx / AG-xx；验收 AC-xx；PR #<编号>

## 背景

当前问题是什么，为什么必须现在决定。

## 候选方案

| 方案 | 描述 | 优点 | 缺点 | 风险 |
| --- | --- | --- | --- | --- |
| A | | | | |
| B | | | | |

## 决策

选择：<方案>
理由：

## 影响

- 后端：
- 前端：
- 数据库迁移：
- 功能开关：
- 对旧流程的影响：
- 需要同步修改的文档：

## 回退方式

代码回退方式 / 数据兼容性 / 依赖的外部能力是否可关闭。

## 验证方式

执行命令 + 预期结果 + 未执行项及原因。
```

---

## 填写要求

1. 一次决策围绕一个明确问题，不与功能实现混在同一提交。
2. **必须写明"对旧流程的影响"**——委托支线不得破坏既有自主发货/船东/订单/支付/Agent 行为（AC-01）。
3. 涉及数据库的决策，代码回退与数据库回退**分别说明**，不默认 `downgrade` 安全。
4. 否决的方案也要保留记录，避免重复讨论。
5. 决策被后续变更取代时，原文保留、状态改为"已取代"并指向新记录。
