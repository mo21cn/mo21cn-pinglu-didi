## 一、0010：七槽位早已定义，当前发生了需求基线查找错误

0010 声称"所有文档与设计稿均未枚举七槽位"，这个判断不成立。

原英文 PRD 第 4.3 节 `Assignment workbench slots` 已逐项列出七槽位。检索中文"槽位"没有命中，不能据此判断英文文档没有定义。此前生成的八屏线稿 UI-05 也采用了同一套枚举。

这同时暴露出材料同步问题：我在当前仓库目录中没有找到那份具名 PRD。应先把权威版本纳入 `docs/entrust/`，让开发 Agent 能直接引用具体文件和章节。**原 PRD**〔源文档此处断句，照录〕

七槽位按下表执行，不采用 0010 新提议的 A 方案：

| 稳定 key（建议） | 槽位名称 | 主要内容 |
| --- | --- | --- |
| `overview` | 委托概况 | 客户、服务主体、货物、路线、时间、负责人、缺项 |
| `plan_tasks` | 方案与任务 | 方案版本、运输段、任务、前置条件 |
| `procurement` | 采购与报价 | 船东／供应商报价、比价、采购确认 |
| `customer_contracts` | 对客方案与合同 | 对客报价、客户接受、合同及签署证据 |
| `execution` | 履约与交接 | 运输与作业事件、数量、交接凭证 |
| `exceptions` | 异常与变更 | 异常案件、影响检查、处理与确认记录 |
| `settlement` | 费用与结案 | 应收应付、争议费用、结算与结案条件 |

0010 的 A 方案把"采购与报价"和"对客方案"合并，又把附件独立占了一槽，会削弱我们此前强调的内部采购与对客承诺分离。

附件应作为共享证据能力：提供统一材料入口，并关联到各槽位的任务和成果，不必占用七槽位之一。

0010 还需改正四项执行规则。

### ① 七槽位不等于七个表、七类成果或七个接口

一个槽位可以读取多个业务对象；同一个附件也可关联多个成果。

建议先提供一条单委托工作台聚合查询，返回七槽位摘要，详情按需加载。后端负责权限、状态和可执行动作，前端负责展示与跳转。

### ② 两个 Agent 专业，不等于恰好两个槽位有 Agent 按钮

"方案与采购 Agent"可以同时服务"方案与任务"和"采购与报价"。

按钮是否出现，应由以下条件决定：

> 该动作已有实现 ＋ 专业能力已启用 ＋ 用户有权限 ＋ 当前上下文满足要求。

删掉"恰好两个槽位出现 Agent 入口"的验收断言，改成检查每个入口是否对应真实能力和正确作用域。

### ③ 不接受把其余槽位跳到"后续开放"，却把 UI-05 标为完整

可以分 PR 实现，但首版验收时，范围内的槽位必须有可用人工操作。

开发中暂缺能力可以明确标注；它属于未完成项，不能作为正式交付的操作落点。没有 AI 的槽位仍应能人工编辑、记录、确认。

### ④ "下一责任方"和"未决问题"按任务与业务事实推导

最低规则可以直接确定：

- **下一责任方**：下一项可执行／待响应任务的责任人或责任角色。
- **未决问题**：缺项、待确认、失效成果、阻断条件、未关闭异常。
- **最后更新**：相关业务记录的最近更新时间，不能用页面刷新时间。
- **当前成果**：有效业务版本；多个成果时显示摘要与数量。

"确认装卸费承担方"应根据上下文落在采购或对客方案相关任务中，不能因为含有"费用"就统一归到结算。

另外要区分"暂无记录""尚未分配""不适用"和"信息缺失"，不能把所有 `null` 一律显示成"待补充"。

## 二、0011：注册表方向正确，但目前不能证明运行期导航安全

我检查了仓库中的 `routes.js` 和 `verify_routes.js`，并对其中纯函数做了针对性验证：

| 验证 | 当前结果 |
| --- | --- |
| 不带 `assignment_id` 调用 `resolveNavigation()` | 仍返回 `navigateTo` |
| 深链参数为 `assignment_id=` | `canDeepLink()` 返回通过 |
| 参数值为任意文本 | 仍返回通过，没有类型校验 |
| 声明"工作台↔会话"双向来路 | `chainDepth()` 返回 `Infinity` |

最后一项直接触及产品要求：经理人必须能在会话、工作台、成果详情之间反复切换。

有循环的业务导航不一定造成无限压栈。例如，返回已有工作台可以复用现有页面；替换页面也不会每次增加一层。因此，不能把所有导航关系都当成父子树，也不能把所有循环都判成错误。

建议采用"**修正版 B**"：保留登记与门禁，新增委托页面同步接入运行期治理。

| 当前设计 | 修正要求 |
| --- | --- |
| `parents` 同时表示页面层级与所有来路 | 分开表达"界面层级"和"导航边" |
| 导航边不区分操作 | 标明 `push`、`replace`、`back/reuse`、`switchTab`、`reLaunch` |
| 所有循环都失败 | 检查可能持续压栈的循环；允许有明确复用／返回策略的双向导航 |
| `kind=root` 被当成自动清栈 | 页面类别不决定清栈，实际调用的导航操作才决定 |
| 参数只检查键是否出现 | 检查非空、类型／枚举，以及相关 ID 是否属于同一业务上下文 |
| 注册表落地但页面不调用 | 新委托页面必须接入；旧页面按触及范围逐步迁移 |

无需现在建设复杂的全程序导航分析器。声明校验、运行期保护、关键路径行为测试三者组合，已经足够支撑本阶段。

## 三、运行期导航应采用明确策略，避免默认覆盖当前页面

现有 `go()` 接近栈上限时默认改用 `redirectTo`。这可能卸载尚未保存的编辑页面，也会改变返回路径，不能成为所有页面的通用默认动作。

建议按顺序处理：

1. **目标已在栈中，且业务上下文相同**：优先返回／复用，并刷新目标成果。
2. **正常进入下一级，预算允许**：使用正常压栈。
3. **明确允许替换的同级页面**：保存必要上下文后替换。
4. **涉及未保存编辑**：先保存或提示处理，不静默卸载。
5. **仍无法安全进入**：给出明确提示及返回工作台的操作。

页面复用不能只比较路径。例如，同一个成果详情页面可能分别显示两张委托，必须比较：

> 页面路径 ＋ 委托 ID ＋ 必要的任务／成果／会话 ID。

保留 `STACK_BUDGET = 8` 作为项目预算可以，但它只是策略。把临时页面留在声明之外，再预留两层，并不能保证实际栈安全。

**深链校验必须落在目标页面入口。** 内部 `go()` 校验之外，冷启动或外部进入时仍需执行入口守卫：

- 参数是否合法；
- 是否登录及有访问权；
- 成果、任务、会话是否归属所给委托；
- 是否需要选择组织或恢复上下文。

"缺少上次选择的组织"可以进入选择流程，并非必须禁止该页面深链。`deepLink=deny` 也不能代替服务端授权。

## 四、两个决策可以这样分工，立即解除执行困惑

| 事项 | 产品定案 | 开发 Agent 自行落实 |
| --- | --- | --- |
| 七槽位名称与业务边界 | 采用原 PRD 第 4.3 节 | 投影查询、组件、字段与详情落点 |
| Agent 按钮 | 按真实动作能力出现，不限定槽位数量 | 能力／权限／上下文判定 |
| 首版人工操作 | 范围内必须可用 | 表单、任务动作、证据录入 |
| 非线性切换 | 支持工作台、会话、成果反复切换并保持上下文 | 导航策略、状态恢复 |
| 页面栈预算 | 保留项目预算 8 | 实际栈检查、复用、替换和失败处理 |
| 旧页面改造 | 不要求全量重写 | 新页面必接入，旧页面按影响范围渐进迁移 |

建议补充的验收用例：

1. 七槽位顺序、稳定 key 与约定一致。
2. 每个槽位的人工操作有真实落点；Agent 按钮对应真实动作。
3. 工作台→会话→成果→工作台连续循环二十次，栈深保持受控，上下文不串单。
4. 两张委托使用同一路径时，不错误复用数据。
5. 缺参、空参、非法参数在目标页入口被拦截。
6. ID 合法但无权限／归属不一致时，不返回业务数据。
7. 接近预算且有未保存编辑时，不静默丢失内容。
8. 测试报告区分静态校验、Node 行为测试、真后端集成和设备走查。

## 五、可直接回复开发 Agent 的六条（原文照录）

对 DR-0010 / DR-0011 的处置意见：

1. DR-0010 按原 PRD 第 4.3 节修订：委托概况、方案与任务、采购与报价、对客方案与合同、履约与交接、异常与变更、费用与结案。不采用新增的 A 方案。补齐权威 PRD 的仓库路径与章节引用，删除"七槽位未定义"的判断。

2. 槽位、数据聚合和 Agent 专业不是一一对应关系。Agent 入口按已实现动作、用户权限和当前上下文展示，删除"恰好两个槽位有 Agent 入口"的断言。范围内人工操作必须有真实落点，不以"后续开放"作为验收完成。

3. DR-0011 保留注册表、双向登记检查及预算 8。分开建模页面层级与导航边；导航边注明 `push`／`replace`／`back`／`reuse`／`reset` 等策略，不将正常的工作台与会话双向切换一律判为非法循环。

4. 不要求全量改造旧页面，但新增委托页面必须从首个切片起使用导航治理与目标页入口校验。不得把未接入页面的工具函数描述成已完成运行期保护。

5. 修复空参数校验、上下文复用和接近栈预算时的处理。禁止默认 `redirectTo` 导致未保存内容丢失。补充循环导航、跨委托、非法参数和入口鉴权测试。

6. 以增量 PR 修订现有代码与决策记录，保留已完成成果。UI-05 的槽位定义阻塞可以解除；接口和导航实现细节由开发继续落实。
