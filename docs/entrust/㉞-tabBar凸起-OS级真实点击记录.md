## 1. 为什么必须另开一条通道

㉞ 章把这一跳记成 `NOT_RUN`，原文是：

> `[data-key='publish']` 命中 0 个（自定义 tabBar 是**组件**，不在页面级查询范围内；
> 客户端也没有坐标点击 / 组件作用域查询通道）⇒ 本跳改用 URL 直进发布货源页……
> 要补上这一跳得另开 OS 级鼠标通道（与 ⑧b 原生弹层同一类手段），本切片未做。

这是**工具的能力边界**描述，不是"这件事不可验证"：
凸起在屏幕上真实存在、真实可点，只是**不在小程序页面的渲染树里**，
所以元素工具（`automation_element_action`）够不着它。
⇒ 换通道：操作系统级输入（Win32 `SendInput`）。

与 ⑧b（原生弹层确认键）是**同一类手段、两件不同的事**；⑧b 那两轮证据在
`H3-原生弹层确认键人工验证记录.md`，本文件只记 tabBar 这一处。

**结论：凸起被 OS 级真实鼠标点中 —— 页面栈 1 → 2、落在 `pages/publish/cargo/cargo`。**

| 项 | 实测值 |

### 证据链（四段，缺一段都不成立）

1. **定位叠加图** `02-定位叠加.png`：绿十字 + 红框正落在凸起上，且**只有一个候选**
   （无橙色落选框）⇒ 证明点的是那个按钮，不是"蒙对了一个坐标"。
2. **光标落点校验**：偏差 1px（判据 >3px 即告警）。
   ⚠️ 这条不是形式主义：多屏环境下漏掉 `MOUSEEVENTF_VIRTUALDESK` 会让绝对坐标被投影到
   **主屏**，光标落在几百像素外，表现为"点了全无反应"，看起来像 SendInput 被拦。
3. **对照点击（防"蒙对"）**：在同一条 tabBar 上、**同一 y**、向左偏移 84px 点一次
   ⇒ 落到 **`pages/trade/orders/orders`**、**栈深仍为 1**。
   ⇒ 两条结论同时成立：① OS 输入**确实到达了应用**（不是发出去没人收）；
   ② 同一条 tabBar 上**只有凸起**会 push（其余是 `switchTab`，栈深不变）。
   复位现场用客户端 `switchTab` —— 那一步只是复位，**不算证据**。
4. **页面栈 +1 且落页正确**，并叠加 OS 截屏 `04-点击后-OS截屏.png`
   （开发者工具底栏自述 `页面路径 /pages/publish/cargo/cargo`）+
   页面默认态出现（发布货源页进入即弹「发货方式」选择，`showChannel=True`）。

### ⚠️ 执行者如实标注

本次点击由**自动化输出的一个真实鼠标事件**完成（`SendInput` 发 move + down + up），
与手指按下去是**同一条输入路径**；但它**不是"人手点的"**。
记录里**不写**"已人工验证"，也**不写**含糊的"已执行"。
