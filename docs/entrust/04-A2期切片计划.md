## 5. 前置问题 —— **P1 / P2 已裁决**

### P1 ✅ 已裁决 —— **(b)**：A2 出口只含 17～19；验证 20 与验证 10 归属 S3

* **裁决**（2026-09-15 HO）：

  | 项 | 裁决 |
  | --- | --- |
  | A2 出口 | **验证 17～19** 通过，并完成相应接口、页面与真实载荷验证 |
  | 验证 20 / 验证 10 | **明确归属 S3** —— 正式结案命令首次上线即接入 |
  | A2 已有任务执行门禁 | 保留，继续复用**唯一**阻断判据 |
  | R1 出口 | 验证 20 及**完整结案条件仍必须通过**，**没有取消或降级** |

* **理由**（HO 原文要点）：正式结案还依赖任务处置、交接证据、结算批准、未结余额等条件。
  只检查异常就允许结案 ⇒ **给系统增加一个错误的业务出口**；
  若命令永远拒绝结案 ⇒ 只能证明一个**测试壳**。
  ⇒ **本期不做仅用于挂门禁的最小结案命令。**
* **执行要求**：A2 可保留内部的「查询阻断案件」能力及测试，
  但**不得**把它算作「真实结案请求被拒」的验收证据。
* ⚠️ 已具备的判据**仍不得复制第二份**（B6）—— 复制就会出现
  「执行命令认阻断、结案不认」。

### P2 ✅ 已裁决 —— 采用混合映射，冻结为 [DR-0016](decisions/0016-变更影响映射.md)

* **裁决**（2026-09-15 HO）：**「业务变更 → Artifact + Task」显式混合映射**，
  按五行映射冻结实施契约；**交接计划落 `handover` 任务；路线与适配落 `execution` 复核任务**；
  **不存在的成果类型不得虚构**，缺少真实关联时要求人工确认影响范围；
  **供应商原报价保留原样，只复核其适用性**。
* 该表冻结的是**复核范围**，**不是自动改写清单**（DR-0016 §4 四条解释）。
* **不再就五行映射发起一轮 HO 选择**；五之二直接引用 DR-0016。

### P3 顺序（本计划自行裁定）：A2 与 DR-0015（会话屏）可并行

DR-0015 只闭合 AC-05 的**成果卡**那一半，**不依赖 A2**；
但两者都会碰 `capabilities`：**必须由一处产生**（DR-0014 已定为单一来源），
不得各加一个字段。HO 裁决亦确认：**DR-0015 可继续并行，`capabilities` 保持单一来源**。

### P4 ⚠️ 新增（HO 裁决）：五之一的实施前提 —— **批准内容必须能被机器精确核对**

现状 `_assert_basis_revision()` 只检查「版本是否存在、是否属于本委托」，
**没有**检查它是否仍是**批准时适用的版本**；单个 `basis_revision_id`
也不足以覆盖**多目标**批准范围。⇒ **五之一开工时先定死**：

| # | 前提 | 说明 |
| --- | --- | --- |
| A1 | **每个应用目标**的 `target_kind`、`target_id`、**基础版本** | 逐目标，不是案件级一个 |
| A2 | **经过批准的结构化修改内容** | 不是把文本塞进决定备注 |
| A3 | **批准事件**与上述内容的**绑定关系** | 应用时按此核对 |
| A4 | **逐目标核对版本**，**拒绝临时替换修改内容** | 与验证 17 的 409 同一语义 |
| A5 | **纯任务变更**也要有自己的**版本依据** | **不得**为满足字段要求而虚构一份成果 |
| A6 | 优先评估**复用现有事件 `payload_json`** 保存**有校验契约的批准快照** | 若现有结构不足，**允许追加迁移** |
| A7 | **统一事务**：应用更新 + 事件 + 幂等结果 | 失败**不留部分业务更新**；成功重试**不重复副作用** |
| A8 | **拒绝事件**按失败审计规则保存 | **不能因业务回滚而丢失** |

> ⚠️ 因此 **「五之一无迁移」降级为「实现评估结果」** —— 本计划 v1 写的
> 「不需要新迁移」是**推测**，不是实测；**必要时允许追加迁移**。
> 另：现有成果与任务服务存在**自行 `commit()`** 的调用路径，
> 五之一必须提供**可由外层统一管理事务**的调用方式。
