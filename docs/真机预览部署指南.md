# 真机预览部署指南 —— 手机微信体验本机实例

> 目标：手机微信扫码打开小程序，后端跑在开发机上（Windows）。**不需要域名、不需要备案、不需要等审核**。
> 适用场景：开发自测、内部演示、给甲方看真机效果。

---

## 一、为什么不能直接用 127.0.0.1

手机和电脑是两个独立的设备。小程序里的 `127.0.0.1` 指向**手机自己**，请求永远到不了电脑。

所以真机必须走电脑的**局域网 IP**：

```
手机微信（预览版小程序）
      │  HTTP  →  http://192.168.0.178:8000
      ▼
开发机  uvicorn 监听 0.0.0.0:8000
      │
      ▼
SQLite pinglu_didi_dev.db
```

## 二、前置条件（缺一不可）

| 项 | 要求 | 检查方式 |
|---|---|---|
| **AppID** | 已注册的小程序；当前微信号是该小程序的**管理员或开发者** | 开发者工具「详情」页可见 |
| **网络** | 手机与开发机连**同一个 WiFi**，同一网段 | 见 3.1 |
| **后端监听** | 绑 `0.0.0.0`，不是 `127.0.0.1` | `netstat -ano \| findstr :8000` 应见 `0.0.0.0:8000` |
| **防火墙** | 放行 8000 入站 | 见 3.3 |
| **开发者工具** | 勾选「不校验合法域名」 | 右上角「详情 → 本地设置」 |
| **手机端** | **打开「开发调试」** | 见第五节 —— **最容易漏，漏了必失败** |

## 三、让后端对外可达

### 3.1 查本机局域网 IP

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' } |
  Select-Object IPAddress, InterfaceAlias
```

取**以太网 / WLAN** 那一项（本项目实测 `192.168.0.178`）。
`100.64.x.x` 属运营商级 NAT 段，手机访问不到，**不要用**。

### 3.2 以 0.0.0.0 启动后端

```bash
cd backend
"C:/Users/Administrator/.venvs/pinglu-didi/Scripts/python.exe" -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

> `uvicorn app.main:app` **默认只绑 127.0.0.1**。`app/core/config.py` 里的 `HOST` 字段是项目自定义
> 配置，uvicorn CLI 不会读它 —— 必须显式写 `--host 0.0.0.0`。

### 3.3 放行防火墙

```bash
netsh advfirewall firewall add rule name="pinglu-didi-dev-8000" dir=in action=allow protocol=TCP localport=8000 profile=private,domain
```

### 3.4 自测

```bash
# 必须绕过本机代理，否则可能被代理拦成 502
curl --noproxy "*" http://192.168.0.178:8000/healthz
# 期望：{"status":"ok","env":"development"}
```

## 四、小程序指向局域网地址

`miniapp/utils/request.js` 已内置按平台自动切换，**无需手改**：

| 运行环境 | 使用地址 |
|---|---|
| 开发者工具 / Node 校验脚本 | `http://127.0.0.1:8000`（CI 基线，勿动） |
| **真机（iOS / Android）** | `http://192.168.0.178:8000` |

换网络或换机器后 IP 会变，两种改法：

- 改 `request.js` 里的 `LAN_BASE_URL` 一行；或
- 不改代码 —— 在开发者工具 **Storage 面板**加 `dev_base_url = http://新IP:8000` 覆盖

### 填入 AppID（已完成）

`miniapp/project.config.json` —— **已填好**：

```json
{ "appid": "wx4a57f29bc38ca11d" }
```

> 占位值或游客模式（`touristappid`）**无法生成预览二维码**，必须先填真实 AppID（已完成）。
>
> ⚠️ AppID 固定为 `wx` + 16 位小写字母/数字 = **18 位**。**位数不对时工具不会报「格式错误」**，
> 而是静默降级为游客模式（点预览没反应、真机调试灰显）—— 详见第八节「游客模式」。

⚠️ **若工具里仍显示游客态，去检查 `miniapp/project.private.config.json`** ——
这个文件（被 `.gitignore` 忽略、不入库）里的 `appid` **优先级高于公共配置**。
它写成 `touristappid` 会把上面的真实 AppID 覆盖掉，表现为「预览」按钮提示需要真实 AppID，
而公共配置里明明已经填好了 —— 极易误判成配置没生效。本机已同步为真实 AppID：

```json
{ "appid": "wx4a57f29bc38ca11d" }
```

## 五、登录模式（当前已就绪，开箱可用）

`miniapp/utils/auth.js` 会**按是否配了真实 AppID 自动选择**，不需要手改开关：

| 配置 | 登录方式 | 实际身份 | 适用 |
|---|---|---|---|
| AppID 仍是占位值 | 固定身份 code（`seed-shipper` / `seed-owner`） | 演示账号 | 无 appid 的本地开发、CI |
| **AppID 为真实值** | **真实 `wx.login`** | 见 5.1 预览回退身份 | 开发者工具已填、真机预览 |

### 5.1 预览回退身份（当前状态，真机现在就能用）

真机预览**必须**填真实 AppID（否则生成不了预览码），但这是个全新 AppID ——
`wx.login` 返回的真实 code **每次登录都不一样**，而后端此刻通常还没有 `WX_APP_SECRET`。
若直接拿真实 code 当身份，每次登录都会注册一个**全新空账号**：订单页不报错、走「暂无订单」
空态，看起来和功能故障一模一样（2026-09-11 报的「订单页面仍然空白」就是这一类）。

所以客户端在走 `wx.login` 时会**附带一个预览回退身份** `dev_code`（该角色对应的演示账号 code）：

| 后端凭据状态 | 实际使用的身份 |
|---|---|
| `WX_APP_ID` + `WX_APP_SECRET` 齐备且 `WECHAT_MOCK=false` | 真实 openid（由微信号决定，天然稳定） |
| 其余情况（**当前**） | `mock-openid-seed-shipper` 等演示账号 |

→ 结论：**现在扫码即可看到完整数据**（货源 / 船舶 / 订单 / 泊位 / 预约）。
补齐 AppSecret 后这层回退自动失效，客户端与后端**都不需要改代码**。

> 后端每次回退都会打 `WARNING` 日志（`回退预览身份 openid=...`），方便确认当前走的是哪条路。
> ⚠️ 回退**仅非生产环境生效**：`APP_ENV=production` 时一律拒绝（防 `seed-*` 冒充演示账号）。

### 5.2 模式 A：固定身份（不配真实 AppID）

后端 `WECHAT_MOCK=true`（`backend/.env.development` 已默认），点「货主 / 船东」直接登录
演示数据账号，货源、船舶、订单、泊位全都有。

> ⚠️ 但**没有真实 AppID 就生成不了预览二维码**，所以这个模式实际上只能在模拟器里用。

### 5.3 模式 B：真实微信登录（想用自己的微信号身份）

真实 `wx.login` 的 openid 由微信号决定、天然稳定。需要四处配置：

**① `miniapp/project.config.json`** —— 已填真实 AppID ✅（`wx4a57f29bc38ca11d`）

**② `backend/.env.local`**（不入库，优先级高于 `.env.development`）：

```ini
WECHAT_MOCK=false
WX_APP_ID=wx4a57f29bc38ca11d
WX_APP_SECRET=你的AppSecret
```

> `WX_APP_ID` 已写入 `.env.local`；`WECHAT_MOCK=false` 与 `WX_APP_SECRET` 目前仍是注释状态，
> 补上这两行即切换为真实登录。
> `WECHAT_MOCK=true` 保留在入库的 `.env.development` 里不动 —— CI 依赖它跑校验。

**③ 重启后端**（配置是启动时加载的）

**④ 把演示数据绑到你的真实账号**

`seed_demo.py` 的数据挂在 `mock-openid-seed-*` 演示账号下。真实登录拿到的是**全新 openid**，
在库里是一个空账号 —— 于是「我的货源 / 我的订单」全空，**看起来和功能故障一模一样**。

```bash
cd backend
# 先预览会迁移多少条
python scripts/bind_demo_to_openid.py --dry-run
# 确认无误后执行
python scripts/bind_demo_to_openid.py
```

脚本会把货源 / 船舶 / 订单 / 支付 / 泊位预约整体归属到你的账号，并补上三角色权限
（货主 + 船东 + 港口方），之后手机端重新进入即可看到完整数据。

> 迁移后 `orders.shipper_id` 与 `owner_id` 指向同一账号，即同一微信号既当货主又当船东；
> 撮合时可能推荐到自己的船，属预期行为。

## 六、编译 → 预览 → 手机开调试

1. 微信开发者工具打开 `miniapp/` 目录
2. 右上角「详情 → 本地设置」→ 勾选
   **「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**
3. 点工具栏「**预览**」→ 生成二维码
4. 手机微信（须为该小程序的**管理员 / 开发者**）扫码打开

### ⚠️ 关键第 5 步：手机端打开「开发调试」

**开发者工具里那个勾选框只对电脑上的模拟器生效，真机上不生效。**
所以「手机被拦、电脑一切正常」是必然现象，**不是后端问题**。

真机放行必须在**手机上**单独开启：

> 手机打开小程序 → 点右上角「**···**」→ 点「**开发调试**」（部分版本叫「打开调试」）
> → 提示重启 → **重启后生效**（生效后屏幕左下角会出现 vConsole 绿色按钮）

不开这一步，手机上必定报 `request:fail url not in domain list`，
在小程序里表现为弹窗「**请求域名未通过校验**」，或对话页提示
「（未获得回答，可重试或换个问法）」。

> 💡 **弹窗文案会按运行环境分流**（`miniapp/utils/request.js` 的 `describeError`）：
> 在**真机**上它直接告诉你「点右上角 `···` → 开发调试」；
> 只有在**电脑模拟器**上才提示去改工具设置。
> 若手机上仍看到「让去勾选不校验合法域名」，说明跑的是旧包 —— 重新预览即可。

#### 同一个报错的第二种成因：手机与电脑不在同一网段

即使 Wi-Fi 名字相同、双方能互相 `ping` 通，只要**网段不同**
（例如电脑 `192.168.0.x`、手机 `192.168.1.x`），微信客户端仍会拦下请求，
报**完全相同的** `url not in domain list`。所以「已经开了开发调试还是不行」时，
第二件事就是核对网段：

- **电脑**：命令提示符执行 `ipconfig`，看「以太网」的 IPv4 地址（本文场景为 `192.168.0.178`）
- **手机**：Wi-Fi 详情里看 IP，**前三段必须与电脑一致**（`192.168.0.xxx`）

> 典型陷阱：路由器同时广播 2.4G / 5G 两个 SSID，或开了访客网络 ——
> SSID 看着是一套，实际分属不同网段。让手机改连另一个频段即可。

#### 每次重新预览都要检查这个开关

「开发调试」是**按预览版本**记状态的。重新点「预览」生成新二维码、或从
「最近使用的小程序」再次进入后，建议先确认这个开关还开着（看 vConsole 按钮在不在）。
它是本项目真机调试最容易反复踩的一步。

## 八、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 手机报 `url not in domain list`／弹窗「请求域名未通过校验」 | ① 手机端没开「开发调试」；② 手机与电脑不在同一网段 | 第六节第 5 步（含「第二种成因」） |
| **对话页提示「（未获得回答，可重试或换个问法）」** | 同一原因：请求被拦后走了失败兜底，**并非 AI 故障** | 同上 |
| 手机报「无法连接后端 192.168.0.178:8000」 | 后端没绑 0.0.0.0 / 防火墙没放行 / 不在同一 WiFi | 第三节全部重做 |
| 电脑能访问、手机不能 | 手机连的是蜂窝数据或另一个 WiFi | 手机改连与电脑相同的 WiFi |
| 换了 WiFi 后失效 | IP 变了 | 第四节，更新 `LAN_BASE_URL` 或 Storage |
| 预览码生成时报「请先填写 AppID」 | AppID 仍是占位值 | 第四节 |
| 登录报「微信登录失败: code been used」 | 同一 code 被重复使用 | 退出登录重进；真实登录每次都会取新 code，正常不会出现 |
| 后端日志出现「回退预览身份 openid=…」 | **正常**：尚未配 `WX_APP_SECRET` | 想换真实身份按 5.3 补齐凭据；否则忽略 |
| 登录报「未配置 WX_APP_ID/WX_APP_SECRET」 | 直连 API（未带 `dev_code`）且未配凭据 | 用小程序客户端登录即可；或按 5.3 补凭据 |
| 首页登录失败、订单页空白 | `WECHAT_MOCK` 与 AppID 配置不匹配 | 见下方「两种配置必须成对」 |
| 能进页面但数据全空 | 已切真实登录，但新账号没绑演示数据 | 第五节 5.3 第 ④ 步 |
| **点「预览」没反应 / 真机调试灰显 / 右上角显示「游客模式」** | AppID 不是 18 位，或工具登录的微信号不是该项目开发者 | 见下方「游客模式」 |
| 手机显示「当前网络不稳定」，但页面**没有**微信胶囊按钮 | 工具被切成了「多端模式」，手机上打开的是多端应用 | 见下方「别把项目切成多端模式」 |

### 游客模式：预览点了没反应 / 真机调试灰显

最容易误判的一类故障 —— 看起来像「后端挂了」或「功能坏了」，实际与业务代码无关。
控制台会打印：`请注意游客模式下，调用 wx.operateWXData 是受限的……API 的返回值是工具的模拟返回`。

按顺序查两件事，**先查 AppID，再查登录**：

| # | 检查点 | 怎么查 | 不合格的表现 |
|---|---|---|---|
| 1 | AppID 必须是 **18 位** | `project.config.json` 与 `project.private.config.json` 的 `appid` | 少一位时**不报格式错**，直接静默降级为游客模式 |
| 2 | 登录的微信号是该项目**开发者** | 工具「详情 → 基本信息」看绑定主体名；右上角头像看登录账号 | 显示「游客模式」、或提示「该用户不是小程序的开发者」 |

**① AppID 位数不对**（本项目踩过：手抄 AppID 漏掉一个字符，只剩 17 位）

微信 AppID 固定为 `wx` + 16 位小写字母/数字 = **18 位**。位数不对时工具不会提示「格式错误」，
而是当成游客项目加载 —— 于是预览无响应、真机调试灰显、上传不可用，**与账号权限无关**。

> 已加自动门禁：`node scripts/verify_miniapp.js` 会直接拦下非 18 位的 AppID。
> 取 AppID 请用公众平台「开发管理 → 开发设置」的复制按钮，**不要手抄**。

处理：改成正确值 → 工具内「详情 → 基本信息 → AppID → 修改」粘贴 → 确定 → 重启工具。

**② 登录的微信号不是该小程序的开发者**

- 用**注册该小程序的那个微信号**登录开发者工具（右上角头像 → 微信快捷登录 / 扫码）。
- 若要用另一个微信号：公众平台 → **管理 → 成员管理**（或「开发管理 → 开发人员列表」）
  → 添加成员 → 角色选 **「开发者」** → 手机微信确认邀请 → 工具重新登录。
  ⚠️ 只被加为「体验者 / 运营者」**不够**，只有「管理员 / 开发者」能用预览与真机调试。

**③ 确认是开发者却仍灰显**（工具已知 bug，两种解法）

- 「详情 → 基本信息」→ 点 AppID 旁「修改」→ **不改值直接确定**（可强制刷新权限态）。
- 完全退出工具（含后台进程）→ 删登录缓存目录 `Weapplogin` → 重新扫码登录。
- 仍不行则升级工具版本（部分稳定版存在登录态异常）。

> 💡 游客模式下 `wx.login` 返回的是工具**模拟 code**，不是真实微信凭证。
> 本项目已用「预览回退身份」兜底（见 5.1），所以**即便停在游客模式，进入后的业务数据依然完整** ——
> 但预览二维码本身必须满足上面两条，游客态生成不了。

### 别把项目切成「多端模式」

工具栏左上角有「小程序模式 ▾ / 多端模式」下拉。**本指南只支持「小程序模式」。**

切成多端模式后，工具会在项目里生成 `project.miniapp.json`、`app.miniapp.json`、`i18n/base.json`，
并把 `project.config.json` 改写成 `"projectArchitecture": "multiPlatform"`。此后手机上打开的是**多端应用**
（原生 App 形态），它是**另一套运行时**：启动页由多端框架自己渲染（品牌 logo + App 名 + 分页圆点），
网络请求走多端自己的调试通道，**不走本指南配置的局域网后端** —— 报错也与后端和防火墙无关。

**典型误判**：多端应用启动页显示「当前网络不稳定」→ 以为后端 / 网络设置坏了。

判定方法（三条都对上，就肯定不是小程序页面）：

1. **没有微信胶囊按钮**（右上角 `···` / `⊙`），也没有状态栏；
2. 页面中心是**品牌 logo + 应用名 + 三个分页圆点**，不是我们的「品牌图 + 请选择您的身份」浮窗；
3. 「当前网络不稳定」这句在本仓库里**搜不到**（我们的离线文案是「⚠️ 未连接后端 <地址> · 点此重试」）。

处理：把工具栏模式下拉切回**「小程序模式」**，再用预览二维码验证业务功能。

> 想确认后端到底通没通，看它的访问日志最直接：手机请求会以**手机的局域网 IP**（如 `192.168.0.130`）
> 出现在日志里。日志里全是 `200 OK` 就说明网络没问题，别再去改防火墙。

### 两种配置必须成对

| AppID | `WECHAT_MOCK` | 结果 |
|---|---|---|
| 占位值 | `true` | ✅ 固定身份，模拟器可用（真机无法预览） |
| **真实值** | **`false`**（且已配 AppSecret） | ✅ 真实登录（最终形态，配合 5.3 ④ 绑数据） |
| **真实值** | `true`（**当前状态**） | ✅ 预览回退身份 → 落到演示账号，数据完整（见 5.1） |
| 占位值 | `false` | ❌ 未配 appid，登录报错 |

> 原先「真实值 + `true` → ❌ 每次登录都是新空账号」这一坑，已由 5.1 的预览回退身份消除。

## 九、为什么不用「体验版」

| | 预览（本文方案） | 体验版 |
|---|---|---|
| 需要域名 / 备案 | **不需要** | 需要（公众平台配置 request 合法域名） |
| 能否用局域网 IP | **可以**（开调试后） | 同样要先开「开发调试」才可用 IP |
| 生成方式 | 工具点「预览」即得码 | 需「上传」→ 公众平台「选为体验版」 |
| 有效期 | 约 25 分钟，过期重新生成 | 长期（约 30 天） |
| 适合 | 开发自测、临时演示 | 分发给体验成员长期使用 |

**域名白名单为什么不能用 IP**：微信公众平台只接受 **HTTPS + 已备案域名**，
不支持 `http`、不支持私有 IP 段（`192.168.x.x` 等）；私有 IP 也无法申请 SSL 证书。
所以「让手机直接访问本机后端」只有**开调试绕校验**这一条路。

## 十一、代码质量检查的两项（提交审核前）

上传代码时，工具「代码质量」面板会报两项「未通过」。两者都**不影响提交审核**，
但性质完全不同：一项该修，另一项是**有意不修**。

### ① 图片和音频资源大小不超过 200 K —— 已修

**这项看的是图片 + 音频资源的合计体积，不是单个文件。**
原先整个项目只有两张图，单个都没超 200 K，但合计超了：

| 文件 | 用途 | 优化前 | 优化后 |
|---|---|---|---|
| `assets/home-hero.jpg` | 首页品牌头图 | 150.0 KB | 106.2 KB |
| `assets/port-map.jpg` | 港口页头图 | 71.0 KB | 54.1 KB |
| **合计** | | **221.1 KB** ❌ | **160.3 KB** ✅ |

处理方式：宽度保持到 1024、JPEG 质量 76，附加 progressive + optimize
（缩分辨率的观感损失比降质量小得多，故优先保尺寸）。
脚本 `tmp/apply_compress.py` 可重跑；原件备份在 `tmp/assets_backup/`，
也可用 `git restore miniapp/assets/` 回退，再在工具里点「**重新扫描**」刷新结果。

> 官方建议把这类非必要静态资源放 CDN、以 URL 引入；本项目没有 CDN 部署，
> 故采用压缩方案。以后往 `miniapp/assets/` 加资源时，注意合计别突破 200 K。

### ② 启用组件按需注入 —— 有意不开

做法是在 `app.json` 加一行 `"lazyCodeLoading": "requiredComponents"`。
本项目**主动放弃**，因为收益与代价严重不对称：

- **收益极小**：全项目只有 1 个自定义组件（`components/port-picker`），
  而且有 6 个页面都在用它，按需注入省不下多少启动时间
- **代价极大**：开启后 `miniprogram-automator` 直接 FATAL ——
  `page.data()` 报 `page node not found`（按需注入改变了页面节点树的暴露时序），
  而**真机走查（162 断言）是本项目最重的质量门禁**，比包体积收益重要得多。
  已做 A/B 验证（去掉该行即恢复，见 `CHANGELOG.md` 的「已知边界」）
- 该项在微信侧属「**建议**」级，**不影响提交审核**

待 `miniprogram-automator` 适配按需注入后重新评估。
